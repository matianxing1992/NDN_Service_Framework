## Interpretation and open boundary

This run confirms ACK, Selection, assignment fetch, grant verification,
post-Selection assembly entry, root/material manifest verification and receipt
verification in one real request. It does **not** establish that the receipt
or bundle fetch corrupted, that runner creation failed, or that ONNX Runtime
execution failed. No runner-ready marker, output, terminal success, repeat
request or qualification verdict was observed.

The first observed production failure boundary is now the liveness contract
around long authenticated materialization and inter-provider dependency
publication: Provider 0 was still materializing selected layers while Provider
1's dependency fetch reached its finite timeout, followed by the requester's
stream-gap failure. This is not evidence for blindly increasing a timeout or
relaxing the protocol. The next bounded work must either establish a reviewed
progress/heartbeat and dependency-timeout contract or reduce/parallelize the
post-Selection material fetch, with a C++ production counterexample and a
fresh run.

Therefore T003, T006, T007 and T009 remain `PARTIAL`; this is not
`QWEN_TWO_PROVIDER_PASS`.

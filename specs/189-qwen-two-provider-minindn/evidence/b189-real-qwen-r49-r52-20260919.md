## Interpretation and changed gate

The first production boundary in r52 is the stream liveness contract while
post-Selection materialization is still silent. The requester has the protocol
maximum `interestLifetimeMs=5000` and `maxEventRetries=8`, so the stream-gap
retry window is finite and independent of the 900-second Provider dependency
fetch budget. A Provider can therefore be fetching or assembling valid
selected material while the requester fails before the first terminal event.

This is not evidence that the material receipt, ORT runner or hidden-state
dependency is corrupt, and it is not a reason to silently remove the stream
gap bound. The next implementation unit must choose and review one explicit
contract: publish authenticated progress/heartbeat events that keep the
request live, or make the request/assembly admission wait observable with a
bounded production state transition. It must include a C++ assertion and a
fresh run with runtime timing enabled. Merely increasing a Python timeout,
reusing a stale run ID, or counting ACK/Selection as execution is insufficient.

T003, T005, T006, T007 and T009 remain `PARTIAL`; this is not
`QWEN_TWO_PROVIDER_PASS`.

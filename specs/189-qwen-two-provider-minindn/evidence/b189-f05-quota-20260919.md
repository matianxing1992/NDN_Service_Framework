## Production change

`RepoCore::putRangeLocked` already reserves `additionalBytes` under
`m_mutex`. The vector `handleStore` path and exact-packet `putDataPacket` path
now compute the same available base:

```text
availableBase = max(freeBytes - reservedRangeBytes, 0)
```

Vector replacement may add its own `oldSize` back after the other reservations
are deducted. Same-object vector writes still abort their own range reservation
before this admission check. Reservation release remains tied to the recorded
identity in `clearRangeReservation`.

# Spec 176 operator-state and GUI evidence

**Candidate**: `UAV-Experimental` working tree, 2026-08-28

## State-model regression

```bash
env LD_LIBRARY_PATH="$PWD/build:$PWD/build/NDNSF-DistributedRepo:/usr/local/lib" \
  ./build/unit-tests \
  --run_test=UavTwoLifecycle/OperatorStateKeepsMissionAndCollaborationViewsSeparate \
  --log_level=message
```

The test returned code 0. It stores mission/part progress, stream-independent
command history, and a bounded collaboration view in separate typed records.
It checks that an acknowledged flight command and a timed-out command remain
reconcilable without changing the collaboration stage, selected provider,
terminal owner, incident/attempt IDs, or deadline. No detector result is
accepted as a flight-control decision.

## Bounded GUI smoke

The real Ground Station GUI was started under Xvfb through the existing
MiniNDN launcher with the mock flight-controller profile, one headless drone,
and `--auto-dashboard-panel-test`:

```bash
sudo -n -E timeout 150s xvfb-run -a python3 \
  Experiments/NDNSF_UAV_GUI_Minindn.py \
  --auto-dashboard-panel-test --no-cli \
  --flight-controller-backend mock --drone-headless --no-start-jmavsim \
  --no-xhost --output-dir /tmp/spec176-gui-panel-smoke
```

The candidate Ground Station log contains all required bounded markers:

- `GS_GUI_READY`
- `OPERATOR_DASHBOARD_SNAPSHOT_RESULT ok=true`
- `OPERATOR_DASHBOARD_PANEL_STATE phase=auto-dashboard-panel`
- `DASHBOARD_PANEL_RESULT ok=true`
- `GS_GUI_EXIT rc=0`

The panel rendered telemetry/readiness, mission/video state, parameters,
preflight, active MAVLink messages, and action gates. The detector worker's
optional model download warning was isolated and did not affect the dashboard
or GUI exit. A separate no-NFD Xvfb startup exits with code 1 and the explicit
`runtime did not become ready` message; it no longer aborts in a joinable
thread destructor. This is a bounded startup-failure check, not a network
acceptance result.

## Boundary

This evidence closes the typed operator-state and GUI-smoke portion of T016.
It does not close PX4 SITL (T020), hardware behavior, or release promotion
(T022). The GUI displays application state derived from validated NDNSF
transactions; it does not turn detector output into direct flight control.

## Candidate and static boundary

本轮使用固定目录
`.codex-tmp/spec190-smollm135m-20260923-retry2/`中的
`HuggingFaceTB/SmolLM2-135M`，通过现有 `llama` profile 生成两阶段、30-layer、显式
`float32` ONNX candidate。manifest digest 为
`sha256:1b4b955d9dfaf28dd270eaa08baaa5d8e6afade2ddbdbb76f94a43dbca4eaecc`；两个 stage
均为 ONNX `FLOAT` initializer，CPU EP session 可创建，未出现
`InsertedPrecisionFreeCast`，hidden/KV/logits 均为 `tensor(float)`。token ids、mask、position
仍按 ONNX 接口契约使用整数类型；这不是把 Qwen3-0.6B FP16 artifact 原地转换，而是新的
model/graph/initializer identity。

首次 real normal Repo run `f32-smollm135m-r1`通过了 launcher、MiniNDN/NFD、ACK/Selection、
placement-bound fetch、assembly worker 和 cache finalization，但 Provider-0 首次在
`CausalPositionInputContractV1::validate()`拒绝了 manifest 的
`llama-causal-position-v1`，错误为 `stateful ONNX causal position policy is incomplete`。
静态审查确认 llama 与 qwen 在该 contract 中使用同一 causal mask/position materialization
公式；修复只扩大允许的两个显式策略值，未放宽空策略、输入名或图签名校验。

## Closure decision

该 gate 证明 all-FP32 smaller candidate 已能越过 llama causal-policy runtime boundary，且在
本次终止前没有观察到模型进程内存不足；它没有证明 Qwen3-0.6B 的内存资格，也没有完成
两 Provider terminal、multi-turn KV、C++ oracle 或 Spec190 性能验收。T003 保持 `PARTIAL`，
T004 保持 `NOT_STARTED`。下一步只处理本轮真实的宿主 swap-free 条件和 Provider-1
dependency-fetch 首边界；不提高资源阈值、不把 `RESOURCE_BOUNDARY`记为 PASS、不绕过 Repo/
protected cache。

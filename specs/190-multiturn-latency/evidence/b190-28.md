# B190-28 — Face-backed exact protected grant transport

## Status

`ADVANCE` for the T006 default-factory transport sub-gate；T006 remains
`PARTIAL` and T007 remains locked.

## First boundary and root cause

B190-27 的 callback 已经证明默认 factory 会被安装，但它直接从内存
`NativeKeyGrant` map 返回 JSON，不能证明 production transport 的 exact
Interest/Data 行为。本轮首先把这个 callback 改成通过 Provider-owned
`DummyClientFace` 的 I/O context 发出 exact、non-prefix Interest，并由
发布端在同一 Face 上回送 grant Data。

第一次有效运行到达 `PROTECTED_RUNTIME_FACTORY_BEGIN`，但在
`exact grant Data fetch failed` 处失败；保留的诊断计数为
`publications=1, dispatches=1, exactInterests=1, data=1`。因此发布、exact
Interest 和 Data 投递均已发生，首个失败点是测试 Data 没有合法签名，
而不是 grant name、Face owner 或 timeout。给 Data 加上与生产发布相同的
Provider certificate 签名后，边界被闭合。

## Changed gate

本 gate 的测试夹具现在执行：

`grant Publish → Provider Face exact Interest → exact signed Data → default
factory fetch → credential/registry verification → assembly → runner →
terminal`。

Fetcher 在 Provider-owned Face I/O context 上 dispatch `expressInterest`，
使用 `CanBePrefix=false`、有限 payload、取消和 deadline；producer 只对
已发布的完整 grant name 回送 Data。失败和超时会取消 pending Interest。
没有修改 Core/Provider wire、Selection、grant binding、cache identity 或
应用公开 API。

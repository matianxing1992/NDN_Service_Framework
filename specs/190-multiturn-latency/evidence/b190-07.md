# B190-07 — stream event budget boundary and direct-start simplification

## r26 boundary (2026-09-23)

r26 used the single-process `--direct-start` path with the current immutable Qwen
INT8 candidate and normal encrypted Repo. MiniNDN/NFD startup, Controller/Authority,
Repo publication, ACK close, Selection, placement-bound fetch, both assembly workers,
`RUNNER_READY`, and real C++ execution were observed. Compact Provider evidence stayed
bounded at about 7 MB per Provider; the r24 observer log-volume failure did not recur.

The run stopped at the first native terminal failure on Provider-1 after roughly 512
token events:

```text
native epoch token event admission was rejected
```

There was no duplicate/out-of-order event evidence, no resource guard stop, and no
model/ORT error. Provider-1 emitted 513 compact evidence updates and then reported
`stage=TERMINAL status=failed`; Provider-0 had the same update count without a terminal
failure. The requester therefore produced no terminal/EOS, checkpoint, KV-reuse, or
three-turn acceptance result. r26 is preserved at
`.codex-tmp/spec190-qwen-int8-direct-prepared/direct-int8-prep-r26/`.

## Static owner review

`StreamRequestOptions::maxEvents` defaults to `512` and includes the stream event budget,
while the Qwen request contract permits `maxNewTokens=1025`. `DI_NativeRequester` projected
the token budget into `GenerationOptions` but left `maxEvents` at its default. The Provider
therefore reached the stream publisher's bounded event admission before the requested token
budget could finish. The requester callback queue default (`64`) was not the first boundary:
the event sink returned false inside `CollaborationContext::publishStreamEvent`, before the
requester's event callback admission path.

This is a native contract mismatch, not evidence that the MiniNDN launcher needs another
wrapper. The direct-start simplification is retained: one profile, one installed native
requester, one MiniNDN start. Required authorization, ACK, Selection, placement, assembly,
execution, terminal, and cleanup checks remain in the production path.

## Minimal Changed gate

Derive the stream event budget from the authenticated generation budget at the native option
projection owner: require at least `maxNewTokens + 1` events so the terminal event remains
admissible. Preserve larger explicit transport budgets and fail closed if the derived value
would exceed the protocol bound. Cover both the public `PreparedModel` path and the maintained
`DI_NativeRequester` configuration path with C++ regression cases; do not change resource
thresholds, add a launcher, or bypass stream admission.

Expected exit: a request with `maxNewTokens=1025` reaches the existing native terminal/EOS
path instead of failing at the default 512-event boundary; a request beyond the supported
generation/event bound is rejected before MiniNDN startup. Removal condition: if a focused
C++ test shows the actual first owner is different, revert this gate and follow that owner.

# Spec190 B190-21 protected assembled ciphertext reuse

## Status

`ADVANCE`; T006 remains `PARTIAL`, and T007 remains locked. This gate closes the
current-process/provider assembled-cache hit boundary only. It does not close
OS restart, online Controller recovery, or the real Qwen/MiniNDN qualification.

## First boundary and repair

B190-20 left the normal protected assembled lookup as an intentional miss. The
first B190-21 implementation therefore had two concrete defects at the next
boundary: cold protected assembly used a request-owned staging basename for its
final directory, and Provider treated a protected disk hit as if it were a
plaintext assembled path. Either defect prevented safe reuse without retaining
another model-sized plaintext copy.

The repair is deliberately limited to the native assembled-cache path:

- ordinary protected entries use a stable directory derived from the canonical
  recipe digest, role assembly-spec digest, and opaque key-reference digest;
  request ID, attempt, grant name/digest, Provider boot ID, and KV state are not
  durable directory identity;
- the durable entry contains `model.onnx.cipher`, `manifest.json`, and the
  signed manifest; lookup validates the protected role, current authorized
  `ProtectedRuntime`, key-reference digest, manifest identity, and file bounds;
- lookup returns a ciphertext descriptor with an empty plaintext path;
  Provider performs current-runtime/AAD authentication and decrypts into fresh
  private request-scoped staging;
- cold assembly no longer assigns the durable ciphertext directory to the
  request cleanup owner; only the plaintext handoff remains request-scoped;
- the Provider's in-memory runner/artifact cache remains grant-bound, so an
  independent grant creates its own runner even when it reopens the same
  authorized durable ciphertext entry.

The existing independent-grant regression initially failed because it still
expected two cold assemblies. Static inspection of `ProviderArtifactKey` and
the durable path showed the intended split: different in-memory grant keys,
but the same key-reference-bound ciphertext directory. The test now asserts
that split explicitly.

## Misses and closure decision

- `static`: production call path and ownership were reviewed; no public API
  change was introduced.
- `compile-link`: affected Provider/assembler/test target and assembly worker
  target were rebuilt successfully.
- `runtime-test`: the named C++ selectors and full 21-case target passed.
- `unobserved`: real OS Provider restart with key/reference recovery, online
  Controller confirmation, current grant/Selection/placement rebinding,
  revoke invalidation, precise missing-layer fetch, tampered durable manifest
  signature verification, and Qwen/MiniNDN remain unmeasured.

**Changed gate:** protected assembled lookup is no longer an unconditional
miss in the native path; it now requires an authorized runtime and a
key-reference-bound authenticated ciphertext, while plaintext remains
request-scoped. **Closure:** `OPEN_FOR_NEXT_BATCH`; T006 stays `PARTIAL` until
the remaining Core restart/authorization and real Provider/experiment gates
are observed. T007 does not start.

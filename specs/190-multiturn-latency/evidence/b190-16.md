**Status**: `PARTIAL` / `ADVANCE`
**Updated**: 2026-09-23 17:09 -05:00
**Scope**: close the Core/Repo durable publication metadata and Repo owner
restart-read boundary identified by B190-15. This gate does not create a key,
recover a serving owner, remove the protected assembler miss, or run Qwen.

## Changed gate

The durable encrypted publication contract now carries six non-secret values
from the Core/crypto owner through the Repo adapter:

- `publicationIdentity`
- `protectionEpoch`
- opaque `keyReferenceId` and `keyReferenceVersion`
- `ciphertextManifestDigest`
- `servingLocator`

`RepoEncryptedLargeDataStore` copies these values into `RepoObjectManifest`.
The filesystem manifest JSON serializes and parses them, so the metadata is
available after the original `RepoCore` owner is destroyed and a new owner is
opened on the same fixed root. The Repo remains ciphertext-only: it does not
create, unwrap, validate, or authorize a key. A Durable commit missing any
required value fails before publication with `DURABLE_METADATA_INVALID`.

The legacy no-options `commitFile` overload remains Transient. Existing source
destruction and explicit generation-fenced release behavior is unchanged.
The protected assembler lookup miss and Provider grant-instance cache identity
were not changed.

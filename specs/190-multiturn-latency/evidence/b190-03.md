## Closure decision

现在支持 `turns[]`，在一次 `Runtime → User.prepare → PreparedModel → Conversation`
生命周期内顺序提交；streaming path 在 `result()` 前打开 `EventReader`，对空读继续等待，
并在首个事件文本 flush 后提供受 `test_only` 保护且有界的 parent/pipe barrier。
MiniNDN launcher 改为一次启动 requester，并生成 per-turn compatibility config、checkpoint
和 oracle log view；默认 profile 为三轮。

之前的 PreparedConversation focused selector 失败点已定位为测试 fixture 在
`Runtime::user().prepare()` 前没有绑定带可路由 Attribute Authority 的 LocalMock
`ServiceUser`，并且没有独立 pump 处理同步 prepare 发布的异步回调；这不是生产
Conversation/EventReader 的失败。T003 fixture 现已在 prepare 前完成 binding，并由 C++
pump thread 驱动 AA/Face。修复后 served-provider 和 two-native-turn selectors 均通过。
随后使用固定 candidate、真实 MiniNDN 上下文和 normal protected Repo mode 执行 run-04。

## Failure boundary

`DI_NATIVE_ENCRYPTED_PUBLICATION_FAILED: NAC-ABE produced no wrapped large-data
MessageKey` occurred during the earlier prepared-conversation fixture after
`NDNSF_INTEGRATION_BOOTSTRAP_READY`. Static diagnosis showed `Runtime::user().prepare()`
was running on an unroutable production `ServiceUser` before the fixture binding and
without a C++ pump. The repaired fixture now binds the environment user before prepare
and pumps while prepare runs; both focused selectors pass. The original failure and
repair boundary remain recorded in [`docs/failure-log.md`](../../../docs/failure-log.md).

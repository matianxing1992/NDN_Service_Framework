## First boundary

The first remaining boundary is a test/source-closure gap, not an observed
authorization failure: production `Provider::serve` installs
`installNativeProtectedGrantFactory` at `Provider.cpp:1643`, and
`NativeProviderHandler` invokes it only after parsing and checking the
Selection projection at `NativeProviderHandler.cpp:1953-2015`, then validates
the returned runtime binding before `GRANT_VERIFIED` at
`NativeProviderHandler.cpp:2053-2078`. However, the existing end-to-end C++
served-Provider fixtures pass a non-empty `testProtectedRuntimeFactory`, which
replaces that default at `Provider.cpp:1922-1923`.

The standalone `spec181-native-grant-integration` target does exercise the
production credential loader and exact-name NDN transport, but it constructs
`ProtectedRuntime` directly (`tests/integration-tests/ndnsf-di-protected-grant.t.cpp:33-84`)
and does not enter `Provider::serve` or an authenticated Selection. Therefore
the current evidence proves the default factory's source wiring and its
component contracts, but not the complete default-factory path from real
Selection through grant fetch, binding validation, assembly, and terminal
response.

## Static findings

1. **P1 coverage gap — default factory bypassed by current end-to-end fixtures.**
   `PreparedRequestCompletesThroughServedProvider` supplies a custom factory
   (`di-prepared-request.t.cpp:2352-2400`); the B190-25 protected assembled
   selectors do the same (`di-prepared-provider.t.cpp:2114-2148`). These tests
   remain valid focused tests of the binding/assembly seam, but cannot close the
   production default-wiring lane.
2. **P1 qualification gap — transport owner is not the fixture Face.**
   `fetchNativeProtectedGrant` constructs its own `ndn::Face` and requests the
   exact non-prefix grant name (`NativeProtectedGrantTransport.cpp:14-49`). A
   LocalMock borrowed `Face` fixture cannot prove this path without either a
   real NFD/route-backed test or an explicitly designed production transport
   dependency. Adding a test-only callback that silently replaces this transport
   would not prove the production path.
3. **P2 credential boundary is otherwise fail-closed.**
   `loadNativeProtectedGrantConfig` requires the configured registry, accepted
   model family/epoch, public-key digest and provider recipient key
   (`NativeProtectedGrantCredentials.cpp:97-167`). The transport caps exact Data
   content at 65536 bytes and hands bytes to the pinned verifier; no permissive
   Data validator is used.

# B190-13 / T006 Core key-reference identity static gate

**Status**: `PARTIAL` / `OPEN_FOR_NEXT_BATCH`  
**Updated**: 2026-09-23  
**Scope**: T006 Core/DI protected key-reference owner and restart identity; no protected

## First production boundary

The first missing owner contract is the handoff from grant verification to durable
protected-material lookup:

1. `NativeGrantVerifier` parses a grant `keyId`, but
   `NativeGrantVerificationResult` currently discards it after unwrapping the content key.
2. `ProtectedRuntime` retains only the secret content key and request-scoped binding. It
   exposes no non-secret key-reference identity that a durable ciphertext manifest can bind
   to after a new process or a new grant.
3. `NativeAssembledEntryContext` authenticates model/recipe/storage identity but has no
   protected key-reference field. A ciphertext can therefore not be proven to belong to the
   currently verified key identity independently of request, attempt, grant, boot or KV.
4. `NativeCanonicalOnnxAssembler` writes normal protected ciphertext below a staging-derived
   directory and `tryLoadNativeCanonicalOnnxRoleFromCache` intentionally returns a miss for
   protected entries. Removing that miss before the identity contract exists would turn a
   retained file into an unauthenticated protected hit.

The smallest next production gate is therefore **key-reference identity propagation and
authenticated binding**, not cache lookup or path reuse.

## Frozen C++ contract for this gate

The opaque reference is derived from the authenticated, non-secret tuple:

`authority identity + provider identity + model manifest digest + protection epoch + grant keyId`

Its canonical digest is a `sha256:` identifier. It MUST:

- remain equal for two valid grants with different request IDs, attempts, grant names,
  grant digests, provider boot IDs and fencing tokens when the underlying authority key
  identity is unchanged;
- change for a different authority, provider, model manifest, protection epoch or `keyId`;
- never contain or serialize the content key, recipient private key, complete grant wire,
  request/KV state, or provider boot state;
- be required in the protected assembled-entry AAD/manifest context; missing or mismatched
  references must fail closed before any plaintext is exposed.

This is an identity/validation gate only. It does not yet choose a stable protected cache
directory, decrypt an existing disk entry, alter `ProviderArtifactKey`, or remove the
Assembler protected miss.

## Changed gate

The gate changes only when a named C++ selector proves, in one run:

- two request/grant bindings with the same authority key identity produce the same opaque
  reference while request/attempt/grant/boot fields remain absent;
- changing `keyId`, epoch, model, authority or provider changes the reference;
- a protected ciphertext sealed with one reference rejects a different reference even when
  the content-key bytes are otherwise available;
- missing/invalid reference metadata is rejected before plaintext output;
- existing Spec189 encrypted-Repo and B190-12 retention selectors remain green.

Compile-only output, a plaintext compatibility-cache hit, a copied digest, or a file's
continued existence does not close this gate.

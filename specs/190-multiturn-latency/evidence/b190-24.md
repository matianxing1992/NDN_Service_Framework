# B190-24 / T006 Provider Production Fetch/decrypt Gate

**Status**: `ADVANCE` / `OPEN_FOR_NEXT_BATCH`
**Updated**: 2026-09-23 20:22 -05:00
**Scope**: Provider-side production envelope fetch/decrypt after Core durable
publication. This is a native C++ path gate, not proof of OS Provider key recovery
or complete T006 authorization rebinding.

## Changed gate

`tests/integration-tests/spec189-encrypted-repo-publication.t.cpp` adds
`ProviderDecryptsDurableEnvelopeThroughProductionFetch` to the existing
`spec189-encrypted-repo` target. The fixture publishes a durable encrypted envelope
through `ServiceUser` and `RepoEncryptedLargeDataStore`, then invokes the production
`ServiceProvider::fetchAndDecryptLargeData` path. The provider retrieves the segmented
envelope through `SegmentFetcher`, performs `WireDecode`, finds the explicitly supplied
current test receive key, runs `hybridAesGcmDecrypt`, and returns plaintext equal to the
original payload. Repo object count remains one.

The receive key is injected with the existing C++ `cacheHybridReceiveKeyForTest` hook.
It represents a current verified key at the Provider boundary; it is deliberately not
claimed as cross-process recovery, old-grant reuse, or NAC-ABE inline unwrap.

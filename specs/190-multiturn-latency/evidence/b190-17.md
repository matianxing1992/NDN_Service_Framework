# B190-17 Durable lookup and Core serving reuse

## 状态

`ADVANCE` / T006 remains `PARTIAL`。本轮关闭了同进程 Core durable
publication 的 lookup-to-serving 原子边界；没有把 Repo metadata hit、Provider
hot hit 或真实 Qwen restart 误报为完整验收。

## Changed gate

`ServiceUser::publishEncryptedLargeDataImpl` 在 Durable publication 中先计算当前
plaintext 的 `contentDigest` 和 `plaintextSize`，再按 Core-owned
`publicationIdentity` 查询 `EncryptedLargeDataRangeStore::lookupDurable`。命中时必须同时
满足稳定 encrypted name、publication identity、当前 content digest/size、当前 key epoch、
当前 opaque key-reference、ciphertext manifest、serving locator、durable source 和首段可读性；
随后把 Repo range source 注册为现有 `LargeDataFilePublication`，直接进入正常 segment
serving。该路径不生成新 Hybrid key、不加密、不执行第二次 `commitFile`。

`Transient` API 和没有 durable options 的旧调用保持原有 request-scoped 行为。Repo
adapter 通过 manifest 扫描实现稳定 identity lookup；缺 metadata、冲突 identity、当前
key-reference 不匹配或不可读 source 仍 fail closed。

## Five-lane review

- `static`：Core publish → durable lookup → range source → segment serving 的 owner/lifetime
  和 rollback 边界已复审；hit 不拥有 transient key lease，Repo durable source 由显式 owner
  负责失效。
- `compile-link`：普通根 `build/` 的 `spec190-protected-material-reuse` 和
  `spec189-encrypted-repo`、`spec188-model-preparation-publication` 均成功构建；DI publisher
  的新 durable transport 保持旧 aggregate initializer 兼容。
- `runtime-test`：`spec190-protected-material-reuse` 7 cases、`spec189-encrypted-repo`
  7 cases、`spec188-model-preparation-publication` 5 cases 全部通过；durable owner
  close/reopen lookup/read 和 Core 同一 identity 二次 publish/serve 均重复 3 次通过。
  二次 publish 后 Repo object 数为 1、Core publication 数为 1。
- `unobserved`：跨进程 ServiceUser 的 key-reference/serving recovery、新 grant/Selection
  rebinding、错误 grant/key/AAD/ciphertext、Provider/assembled zero-material hit、缺对象
  精确 fetch、Provider 新 boot/KV fencing、真实 Qwen/MiniNDN 尚未验证。
- `closure`：只关闭本 atomic gate；assembler 的 normal protected miss 门继续保留，T006
  不完成，T007 继续锁定。

由本记录推导 sanitizer PASS。真实 multi-provider qualification 仍需完整

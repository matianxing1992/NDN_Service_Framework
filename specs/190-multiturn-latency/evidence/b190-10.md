## Runtime restart reuse resolved (2026-09-23)

在保留首次 lookup 失败边界后，第一次修复重跑又暴露了第二个失败边界：lookup 将缺省的
publication.package_manifest_digest 与空字符串比较，而生产 NativeRequestCatalog 将其
规范化为 source.model_manifest_digest。该边界同样保留在本次修复记录中。随后完成两处
最小 C++ 修复并重建受影响 target：

1. `lookupPrepared()` 恢复 root metadata 中的
   `materialReceiptDataName/Digest/Bytes`，并校验 receipt object；
2. lookup 对缺省 `publication.package_manifest_digest` 使用与
   `NativeRequestCatalog` 相同的 `source.model_manifest_digest` 默认值。

`Spec190PrepareReusesCommittedReceiptAcrossRuntimeRestart` 通过。两次 Runtime owner
均使用同一个固定 Repo root：第一次 prepare 的计数为 `lookups=1`、`missIngests=1`、
`publicationCalls=1`；释放并重建 Repo/Provider 后，第二次 prepare 为
`lookups=1`、`missIngests=0`、`publicationCalls=0`，并返回非空 preparation key。
该 C++ selector 证明了 Runtime close/reopen 边界上的 prepare-before-STORE reuse；它仍是
同一测试进程内重新创建 owner，不替代真正 OS 新进程资格或完整 T005 验收。

随后将缺失 source 子对象与取消边界加入 `spec190-repo-lookup-reuse`：root 保留而 source
被删除时，lookup 返回 miss，root-last publish 只恢复该缺失对象，Repo committed object
数量回到原值，root 未被删除；已提交 receipt 上的取消 publish 在副作用前停止，旧 receipt
仍可 lookup；存在但 digest 不一致的 source object 被 typed error 拒绝，没有降级为 miss 或
盲写。新增 filesystem fsync fault injection 后，失败的另一 publication 不会删除旧 receipt，
新 root 也不会伪装成 committed。该 selector 现含 4 cases，连续重复 3 次通过。

## Runtime restart regression boundary (2026-09-23)

新增 C++ production selector `Spec190PrepareReusesCommittedReceiptAcrossRuntimeRestart` 首次
运行失败于第二个 `Runtime::user().prepare()`：固定 Repo 已提交的 receipt 被
`lookupPrepared` 报为 `repository prepared receipt is corrupt or conflicts with the requested
catalog`。第一次 Runtime 的 publication identity 与 root 中保存的 digest 已核对一致；字段级
对照定位为 lookup 恢复了 material manifest/payload 列表，却漏恢复 root 中的
`materialReceiptDataName/Digest/Bytes`，导致 `NativePreparedCanonicalPublication::validate()`
拒绝不完整 receipt。该失败作为本轮 focused failure boundary 保留；修复后必须重建并重跑。

本轮从当前生产调用链静态审查开始。结论是：旧路径的 `RepoSourceProvider::publish`
虽然可以在 root 已存在时返回 publication hit，但它发生在 source load、catalog inspection
和 material preparation 之后，不能证明 `user.prepare(model)` 在拆层/导出/STORE 前复用。
实验启动复杂度不是本轮首因；MiniNDN 仍使用单一 `--direct-start`，没有新增 Python 启动层。

## Changed gate

- `NativeCanonicalPublicationOptions` 增加可选 `publicationIdentityDigest`；完整 operator-pinned
  catalog 的 digest 替代 source-only Repo root suffix，旧 direct publisher 未提供该字段时保留
  source-digest 兼容路径。
- `RepositorySourceProvider` 增加默认返回 `nullopt` 的 `lookupPrepared` port；Repo provider
  在读取大型 source/material payload 前检查 catalog identity、root manifest、对象 manifest、
  layer references 和 reference-only material manifest。已存在但冲突/损坏的 receipt 抛出 typed
  `RepositorySourceError`，不降级为 miss/盲写。
- `ModelPreparationCache` 在 `loadSource` 前调用可选 lookup；命中后保留已验证 receipt，跳过
  `preparePublication`/publisher STORE，并把 payload-incomplete material index 交给后续
  Selection/material fetch。未命中仍走原有 bounded source load 与 root-last publish。
- `lookupPrepared` 与 `publish` 现在共用 Repo publication lock，避免 lookup 读取到 root 已出现
  但依赖对象尚未提交的半提交视图。
- `NativeCanonicalPreparationCatalog` 对 reference-only manifest 只验证 source/graph/initializer
  identity，不在 prepare lookup 阶段 materialize 全部 payload；完整 manifest 仍走原有全量验证。

# B190-10 Cache Identity Miss During Focused Probe

2026-09-23, r29 used the same single `--direct-start` path and normal encrypted
Repo as r28, but reduced the request to `--max-new-tokens 2` to isolate cache,
terminal, and cleanup behavior without another 900-second generation attempt.
The run reached MiniNDN, Provider execution, and the native cache lookup. It was
intentionally stopped after Provider-0 reported `CACHE_LOOKUP_MISS` and entered
`COLD_ASSEMBLY_GATE`; it is not a terminal or protocol result.

The miss is currently correct, not evidence that the cache key should be relaxed.
The retained assembled entries were recipe-addressed and their manifests described
the earlier `precision=float16`, `quantization=none` candidate. The r29 candidate
was `quantization=weight_only_int8` and had a different source/graph identity.
`NativeCanonicalOnnxAssembler` looks up by authenticated `recipeDigest` after
Selection and revalidates model-manifest, graph, initializer, role, adapter and
assembler descriptors, backend ABI, precision, quantization, layout, padding, and
the assembled model digest. Reusing the old entry would therefore violate the
model identity contract.

The r29 encrypted Repo and exact interrupted staging directories were removed
after confirming no MiniNDN, Provider, requester, Controller, or authority process
remained. The immutable assembled cache entries were retained for inspection.

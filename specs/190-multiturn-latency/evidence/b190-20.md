## 首个边界与修复

B190-19 的首个生产边界是：Controller status transition 与 durable protected serving 没有共同的 service-scoped epoch fence。仅删除 `.dkr` reference 不能撤销已经注册的 `m_largeDataFiles` serving owner，旧 IMS name 也可能在版本推进后继续被响应；并发中的旧 publication 还可能在新 epoch 下完成提交。

本轮在 Core `ServiceUser` 中完成以下原子边界：

1. 将 `ControllerVersion` 绑定到 protected publication、durable V2 reference、Repo publication identity 和 IMS owner；严格区分首次 status restore 与真正的新版本推进。
2. 以 `m_protectedReuseMutex` 保护 status capture、durable hit、pending publication 和 serving response；`m_protectedReferenceCommitMutex` 串行化最终 owner/reference commit 与 status transition，避免旧 publication 穿过版本切换。
3. 版本推进时只撤销同一 service 的旧 `m_largeDataFiles`、IMS owner 和 pending publication；其他 service 的 publication 保持可用，Repo ciphertext 不删除。
4. `replyFromIMS` 和 `replyFromLargeDataFile` 的 protected read-side fence 延续到 `m_face.put`，从而不允许 retirement 与实际响应交叉。
5. durable reference I/O 失败保持 fail-closed；V2 缺失/损坏/版本不匹配时按当前版本派生新的 publication identity，可从 Repo manifest 恢复非秘密 metadata；旧 Repo object 保留为 ciphertext-only durable object。

## Verify 对照

- 先兼容过滤再 residency 排序（native `NativePreSplitFirstPlacement::propose`）：
  资格过滤要求 offer 接受候选每个 role、backend 覆盖任一 requirement
  backend、freeBytes ≥ (weight+workspace+activation+transient)×1.10；
  eligible 稳定排序键 = residencyDigests 数降序 → freeBytes 降序 → provider
  升序；单 provider 绑定全部 roles（无 fan-out 的冻结决定）。
- budget/ref tie-break（本卡新增
  `PreSplitPlacementTieBreakResidencyThenBytesThenProvider`）：
  - residency 键：provider-c（1 resident digest、free 3 GiB）胜过
    provider-a/b（0 resident、free 4/5 GiB）；
  - budget 键：同 0 resident 下 provider-b（free 5 GiB）胜过 provider-a
    （free 4 GiB）与 provider-x（free 4 GiB）；
  - ref 键：residency 与 freeBytes 均并列时 provider-a（名字最小）胜出，
    两次 propose 输出逐字段一致（同输入同结果）。
- 非法向量/全拒（本卡新增
  `PreSplitPlacementFiltersIneligibleOffersAndRejectsEmpty`）：
  unaccepted role、backend 不覆盖（tensorrt）、freeBytes 低于
  ~2.36 GiB（1 GiB）→ 各单 offer 被过滤 → `runtime_error("no eligible
  provider...")`；deadline 已过期 → snapshot 非法拒绝；executionAllowed
  false 的 offer → 拒绝。
- lease/device 维度：native 单 provider 策略无 fan-out，device_set/lease/
  wait/rtt/bandwidth/state-saving 评分维度未建模（Python V3 精细化区间）。
- 与冻结 Python proposal 对照：`planner/presplit_first.py::propose_v3`
  逐 role 评分键 (residency tier → estimated_wait_ms → queue_depth → rtt →
  -bandwidth → -state_saving → used_mb → provider) 与 native 共享语义区间：
  residency 为第一排序键、provider 名作为确定性 ref tie-break、逐项
  backend/device(memory)兼容过滤 + 资源不足过滤同向。native 固定
  identity configurationDigest（sha256:34a7cf…，hpp 默认参数）为确定性锚点。
  卡 Steps 的“不做 I/O、不授权、不把 has_model 当 exact residency”在实现中
  保持：residency 仅以 digest 列表计数排序，无模型文件读取/授权/真实
  residency 判定。

# Spec186 T006 NAC-ABE binding ABI repair — 2026-09-13

## Failure evidence

The current Waf build used the explicit
`.deps/nac-abe-spec179-official` NAC-ABE prefix. The separate setuptools child
did not receive that prefix and therefore selected the installed
`/usr/local/include` NAC-ABE headers. A real `NativeServiceUser` construction
then failed during teardown. AddressSanitizer identified the first invalid
operation as:

```text
new-delete-type-mismatch
allocated type: 12864 bytes
deallocated type: 13400 bytes
std::default_delete<ndn_service_framework::ServiceUser>::operator()
```

This was a C++ class-layout mismatch across the compiler boundary, not an
Apptainer or MiniNDN transport failure.

## Repair and verification

`scripts/spec180_native_build.py` now reads and validates
`NDNSF_NAC_ABE_PREFIX` from `build-spec186-r5/c4che/_cache.py` and forwards it
to `pythonWrapper/setup.py`. The forced rebuild showed the explicit include
directory before `/usr/local/include`:

```text
-I.../.deps/nac-abe-spec179-official/include ... -I/usr/local/include
```

The canonical native identity check returned `SPEC180_NATIVE_IDENTITY_OK`.
With the rebuilt extension and the same current framework/dependency closure,
`NativeServiceUser` construction, `stop()`, and destruction returned zero;
the previous `double free` did not recur. A separate corrected-ABI lifecycle
probe also passed with explicit Face shutdown.

Final local binding identity: `pythonWrapper/ndnsf/_ndnsf.cpython-38-x86_64-linux-gnu.so`,
SHA-256 `05ed17c3def34416f9c54fee07a9408db1ac053e5f8334beb2f98a1b06d818db`.
The extension RUNPATH contains the selected NDN-SVS build, `build-spec186-r5`,
and the explicit NAC-ABE prefix. Provider, requester, and authority `--help`
all returned zero; native provider `ldd -r` reported no missing or undefined
symbols. Raw extension `ldd -r` still reports the expected Python C-API symbols,
which are supplied by the embedding interpreter and are covered by the
canonical import/identity probe.

## Boundary

This closes the host binding ABI defect that stopped M01 before MiniNDN. It does
not by itself provide the missing full-protobuf ONNX development prefix, an
exact source-sealed 1.5.3 SIF, a Qwen3 model tuple, or any Tiger single-/two-node
GPU result. T006.c and downstream qualification tasks remain blocked or waiting
for those external inputs.

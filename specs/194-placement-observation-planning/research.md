## Gaps That Spec194 Must Close

1. Core already observes the User ACK path and actual Provider dependency fetches, but their measured values are not wired into the signed Native V3 offer/strategy input as a complete, provenance-bound snapshot.
2. The readiness payload can carry measured resource telemetry, but the V3 ACK path replaces it with `canonicalOffer`; that signed V3 payload has empty resources/residency and zero scalar measurements. The real readiness snapshot therefore does not currently reach native V3 placement.
3. User-side ACK RTT is an end-to-end ACK measurement, not a path-only network RTT. Transfer goodput and transfer cost must use real data-fetch samples and retain the measurement kind.
4. Provider-to-Provider measurements are keyed by consumer, producer and scope, while the fetched Data bytes flow producer → consumer. The snapshot must make this direction mapping explicit, bind Provider boot/topology identities and avoid exposing raw Data names, key scopes, or request payload.
5. Native placement currently optimizes each role independently. `NativeGraphEdge.tensor.estimatedBytes` can provide an optional immutable size estimate, while `NativeDependencySpec.expectedBytes == 0` is ambiguous. Unknown bytes must stay unknown.
6. The legacy Python matrix is not a native production contract and its fabricated fallback numbers cannot establish native C++ behavior or performance.

## Architecture Decisions and Deliberate Limits

- Reuse Core production telemetry as the primary source in V1. Do not launch periodic all-pairs probes and do not call application inference for a “network RTT” measurement. If V4 was negotiated but a directed edge lacks a fresh production sample, mark it missing and use baseline ranking semantics over authenticated V4 non-network fields. Select V3/default only before the request when the complete candidate roster lacks V4 capability.
- Keep transport/sample collection generic in Core. DI owns interpretation of role, graph, cache/residency, model preparation and placement cost. Core must not acquire DI/ONNX meanings.
- Introduce the separately signed `DI_PLACEMENT_V4` offer for the new observation collection rather than changing V3 canonical bytes. Keep V3 and its callers as compatibility fallback.
- Bind every selected observation to the current request/attempt, endpoint identity, offer digest and expiry. A valid signature proves provenance, not freshness, authorization, cache possession, or execution permission; validate each separately.
- Use only current-request candidate digests in Provider residency rows. Do not expose arbitrary cache inventory or material bytes.

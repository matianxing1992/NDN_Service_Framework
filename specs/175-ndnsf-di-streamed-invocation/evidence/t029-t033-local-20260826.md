## Implemented contract

- `APPClient.request_streaming(..., conversation=...)` is additive. Omitting
  the option keeps the existing full-context request path.
- Request-local decode state is never looked up by a later Request or by
  `conversationId` alone.
- A conversation checkpoint is an authenticated, opaque successor capability;
  it is committed only after the complete role-receipt set passes CAS.
- Provider state promotion, host/GPU residency, bounded prefetch, expiry,
  Provider-boot invalidation, and cancellation are owned by the separate
  conversation-state manager.
- `APPClient.request_streaming(..., conversation=...)` now allocates the fresh
  request/generation identity and registers the pending turn before planner
  publication; planner failure aborts that pending transaction, and the
  returned streaming handle retains only the opaque turn identity. APPEND_DELTA
  requires adapter-derived canonical token IDs before publication.
- M11--M14 are explicit host-gate cases. Their evidence schema reports only
  bounded counts and digests; state tensors, prompts, checkpoints, and secrets
  are not emitted.

## Cross-request restore follow-up

The native implementation now has an explicit fresh-request restore seam:
`RoleSpec.conversationStateBinding` performs exact Provider-local conversation
state lookup, completes host-to-device prefetch when needed, pins the restored
entry for runner execution, and releases the pin on both success and failure.
The request-local `DecodeStateIdentityV1` remains fresh; the old request ID and
generation ID are never reused.  For `APPEND_DELTA`, the coordinator extends
the authenticated parent prefix digest/count with the new suffix before
constructing request epoch zero, so the suffix is not misreported as a new
full prompt.

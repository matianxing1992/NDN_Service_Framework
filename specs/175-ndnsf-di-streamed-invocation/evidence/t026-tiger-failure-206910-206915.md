# T026 Tiger functional submission failures — 206910 and 206915

**Date:** 2026-08-29  
**Candidate:** `spec175-runtime-fe285147`  
**Gate:** `multi-provider`  
**Result:** **FAIL before model/request execution**

The current exact SIF, Qwen3.6-27B stateful model, functional bundle, and
candidate-bound pre-submit checks were unchanged between the two bounded
submissions. Both jobs ran on `itiger02` and exited with code `7` before a
Provider became ready and before any model request, Selection, prefill, or
decode was executed.

## Observed failure

The Provider logs reported:

```text
RuntimeError: certificate bootstrap Nack reason=150
```

The NFD trace showed the Controller application face registering the expected
prefixes, followed by that face closing and the Controller routes being
removed. The Provider bootstrap Interests then reached `BestRouteStrategy`
with no next hop. This is why the visible Provider error was `NoRoute`; it was
not evidence of a bad SIF, CUDA runtime, ONNX Runtime, model artifact, or
NDNSF-DI request path.

## Root cause

The staged `controller-wrapper.sh` generated a bootstrap-token file containing
Controller/User/Provider identities, but not the three repository identities
that the wrapper unconditionally requested with `bootstrap_token_for_identity`.
That lookup used `awk` under `set -e`; the first missing repository token
returned status 1, terminated the wrapper, and its `finish` trap killed the
Controller process. The Controller face and routes consequently disappeared.
In job 206910 the earlier route probe also produced a diagnostic
`missing-parameters` refusal. Job 206915 used a unique non-registered probe
suffix and instead exposed `no-token`; the Controller still exited afterward
because the repository token set remained incomplete.

The primary owner is therefore the **functional submission bundle's identity
and process-lifetime closure**. The route probe is not sufficient as a
readiness check unless the wrapper remains alive and its registered routes are
still present after the probe.

## Evidence boundary

These jobs are retained as negative launch evidence. They do not count as
T026 functional invocations, do not provide a model throughput/latency result,
and do not close G6. The next submission must first make the required
bootstrap-identity set explicit, verify token-set closure and child command
arguments without allocating a node, then assert Controller liveness and
route presence while Providers bootstrap. T034 and T027 remain blocked until
T026 has six completed model-level invocations.

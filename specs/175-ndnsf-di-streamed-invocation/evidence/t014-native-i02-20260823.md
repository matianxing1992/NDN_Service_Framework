# Spec 175 native I02 evidence

**Date**: 2026-08-23  
**Case**: `I02` — two Providers, request-scoped epoch coordinator, tiny
stateful ONNX CPU path  
**Status**: `PASS` for the registered I02 case only

## Subject and boundary

This case uses the production C++ `BeginCollaboration` Request/ACK/Selection
path with two selected Providers. Each Provider receives one complete role.
The coordinator executes one unary ONNX Runtime transition per role and epoch,
and carries activation and token-feedback objects as authenticated,
epoch-specific `NDNSF_DATA_V1` objects. The terminal role alone emits the eight
token events and final Response; the upstream role consumes one terminal
feedback drain marker without executing an extra model step.

The feedback edge deliberately leaves `expectedBytes` unspecified: feedback is
an encoded TensorBundle (`input_ids` plus a terminal marker), so its byte count
is taken from the authenticated DATA_V1 manifest rather than a raw token-size
estimate.

The healthy gate also requires both Provider epoch coordinators to report clean
completion and zero native failures. A final-role Response alone is not a pass.

## Qualification boundary

This evidence qualifies I02 for the local G2 registry. I03/I15 are qualified
separately. It does not qualify I04-I14, complete G2, G1, SIF, MiniNDN, CUDA,
or 27B performance gates. Those remain explicit blockers.

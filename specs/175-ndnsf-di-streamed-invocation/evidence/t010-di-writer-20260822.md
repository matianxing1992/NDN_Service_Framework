# T010 DI/Core streamed-writer bridge

**Date**: 2026-08-22  
**Status**: complete for the registered DI/Core bridge contract

## Implemented

- `ProviderRuntimeContext.publish_event()` now accepts only application events
  and returns the Core-committed 1-based cursor.
- `ProviderRuntimeContext.finish_stream()` accepts the named finish reasons
  from the API contract while retaining the old integer spelling as a
  compatibility input. It competes with `publish_final_response()` through the
  same terminal guard.
- `ProviderRuntimeContext.stream_cancelled()` exposes the Core writer's
  cancellation/fence state without creating a second stream state machine.
- The native Python `StreamWriter.publish_event()` now returns the exact cursor
  allocated by `StreamedResponseWriterCore`; rejected publication returns zero.
- The DI/Core integration fixture verifies one cursor, one terminal, and
  post-terminal rejection. Python tests verify named finish reasons,
  application-event rejection, cancellation visibility, and both terminal
  claim orders.

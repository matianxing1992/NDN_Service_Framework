## Defects fixed before this run

1. Provider context metadata was not updated after authenticated COMMIT. The
   next Request therefore saw cached epoch 0 while its delta expected epoch 1.
   The Provider now writes the committed prefix and successor epoch to its
   local context-expansion cache only after promotion commits; state tensors
   remain owned by the Provider conversation store.
2. APPEND_DELTA receipt construction prepended the parent prefix a second time
   even though stage 0 had already materialized the full parent-plus-suffix
   input. The finalized prefix now uses the materialized input followed by the
   new generated tokens and verifies the exact parent prefix first.
3. Conversation request IDs are normalized once at the Python/native boundary
   so the absolute NDN Name component and the coordinator use the same value.

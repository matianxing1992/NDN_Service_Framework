# Bounded Executor Profile

## Activation

用户要求由 Codex Spark 或其他有限范围执行者实施时启用；不根据模型名称猜测能力、额度或自动切换模型。
该模式改变任务交付粒度，不改变产品目标、安全约束、验证阶段或用户授权。

## Preparation

设计者先关闭受影响的接口、算法、所有权及兼容决策，再准备执行卡。
保留已有上层任务 ID 与验收；大任务只沿可独立审阅、合入和验证的行为边界分卡。
一张卡包含该行为的实现、测试编写、源码审查、相关检查与结果记录，不按文件或行政步骤拆分。
未决设计由具备相应能力的设计者处理；执行者不以自由发挥补齐新 API、ABI、安全或状态机语义。

每张卡提供以下信息，共享约束只引用一次：

| Field | Content |
| --- | --- |
| ID / Parent / Outcome | 稳定 ID、上层任务、一个可观察成果 |
| Depends / Readiness | 前置卡与上层任务、控制性缺口；READY 必须有当前证据，不能由存在文档推断 |
| Read | 按顺序列契约章节、源码文件及符号、可复用实现、独立 oracle；区分 existing 与 planned |
| Write | 精确文件与预期新增/修改/删除；只读参考不能进入修改范围 |
| Steps / Invariants | 实现步骤、调用方、输入输出、失败/生命周期约束；普通局部细节留给执行者 |
| Verify | 真实入口、独立预期、负例、命令、环境/超时；未存在工具标 planned，并指定注册 owner |
| Result / Handoff | 当前状态、源码身份、实际命令/退出码/证据、剩余正式验收与下一卡 |

路径以仓库根解析，引用符号或章节而非仅行号。分派时记录实际 commit 与相关未提交 diff；
设计、调用方或依赖漂移时仅重审受影响卡。不要复制完整契约或默认加载整个 contracts 目录。
执行卡的阅读入口必须足以定位事实，不要求执行者先搜索全仓库才能知道要改什么。

## Execution

一次分派一张依赖已满足的卡；多卡授权可在同一逻辑批次连续编码，每卡独立静态审查并记录。卡注明 Batch ID、实现依赖/验收依赖和共享测试负责人；静态通过可交接下一已授权卡，测试待运行保持 PARTIAL，批末统一审查流程与构建/测试。批次不扩大单卡 Write 授权，也不豁免硬前置验收。
先读仓库必须材料与当前 checkpoint，再读选中卡及其定向引用；按仓库要求验证真实调用方。
只修改 Write 范围及明确共享的任务/证据记录。普通局部选择自主完成；需要范围外行为修改时，
记录具体冲突、受影响符号与缺失契约，交回设计阶段。不要启动泛化的项目清理或无关 ignore-file 修改。
必要修复和有界重试留在当前卡；不可把失败卡标完成或默默跳过。无需因剩余未来验收再次请求许可。

## Completion

沿用 [pre-test-static-review.md](pre-test-static-review.md) 的执行与证据规则。
卡完成不等于父任务完成：父任务全部子成果及其本级验收满足才勾选；最终运行义务仍交最终验证任务。
存在执行卡、结构检查通过、模型已被选择，均不证明该模型实测可胜任。
先选有固定设计和独立 oracle 的代表卡，依据实际首次完成、审查修正和越界修改记录调整粒度；
不把执行卡数量、token 用量或速度作为正确性验收。

## Shared Progress

所有模式和执行者统一遵守 [task progress registry](task-progress.md)，不另建 Spark 状态表。

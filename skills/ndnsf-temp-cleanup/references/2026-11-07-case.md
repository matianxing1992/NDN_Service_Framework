# Historical case: 2026-11-07 NDNSF host cleanup

The host had about 30.17 GiB under `/var/tmp` and less than 0.5 GiB ordinary-user free
space. Nonprivileged scans missed root-owned data. `/tmp` itself was only about 2 MiB.
Historical reports live under the checkout, if present:

- `docs/reviews/disk-usage-cleanup-assessment-2026-11-07.md`
- `results/var-tmp-closeout-20261107/README.md`
- `results/var-tmp-closeout-20261107/followup/README.md`

Missing reports do not prevent applying the workflow. Do not execute their historical scripts
against a new inventory: those scripts embed one-shot path allowlists and checkpoints.

## Decisions that mattered

- Preserve active `spec222-stored-model` (about 5.30 GiB). Preserve
  `spec220-campaign-install` (about 3.24 GiB) because current Spec222 still referenced its
  executables despite the older directory name. Current feature names will change.
- Preserve shared Qwen/YOLO model inputs and Repo/Provider caches until identity, current
  purpose, warm/cold baseline and usable retained copies are established.
- Preserve `spec220-requester-heap` for the unresolved heap failure. Cleanliness or age did
  not establish that its reproduction material was dispensable.
- Retire 30 marked idle workspace `work/` directories under exclusive locks, archive 60,077
  source/config/log/input/link entries as 29 archives (about 221 MiB), and retain identities
  for discarded compiled products and stale test sockets. Remove one clean review worktree
  while preserving its fixed commit. Net free-space gain was about 2.30 GiB, less than the
  `/var/tmp` allocation reduction because archives remained on the same disk.
- A second batch used pip/uv cache commands, removed 19 old plugin installation cache files,
  seven exclusive old Snap download files, and a second clean idle worktree. Net gain was
  about 6.57 GiB; free space reached about 9.30 GiB. Installed extensions and recent cache
  files stayed in place. Snap hardlinked files stayed because unlinking them would not yield
  the claimed exclusive-space benefit.
- Trash contained old builds but also source and diagnostic evidence. Codex history and
  archived research traces were not ordinary disposable cache. They were not deleted.

## Implementation pitfalls

- An old test left Unix sockets. Classify inactive endpoints separately rather than attempting
  ordinary-file hashing or silently ignoring them.
- uv uses directory symlinks in its cache. Inventory links without following them; use uv's
  cache cleaner rather than recursively interpreting symlink targets as owned cache data.
- Permission errors during post-delete checks do not prove absence. Recheck with appropriate
  read access and preserve the failed-check boundary.
- This host used Python 3.8. `hashlib.file_digest` is unavailable; use streamed SHA-256 when
  writing a helper for that interpreter. Do not upgrade the system merely to run cleanup.
- Root-owned `results/` required creating only the exact private evidence subdirectory with
  the intended user ownership, not recursively changing permissions on the parent tree.
- No builds, inference jobs, product tests, service stops, commits or pushes were needed.

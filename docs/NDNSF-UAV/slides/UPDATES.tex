\textbf{One concrete task}
\begin{itemize}
  \item The operator clicks a location; the planner selects three camera roles and one GPU-capable Analyzer.
  \item Each camera publishes one encrypted \texttt{ViewImage}; the Analyzer fetches admitted objects by name and processes them.
  \item The Analyzer returns annotations and content-encryption-key (CEK) grants; the Requester fetches the original images and overlays the results.
\end{itemize}
\begin{alertblock}{Proposed first case, not a field demonstration}
A known location narrows the search; pointing, visibility, pose error and cross-view correspondence still need validation.
\end{alertblock}

\evidence{Multi-UAV visual inspection and coverage systems already distribute image-acquisition work across aircraft [1,2].}

\begin{frame}{Practical Boundary, MVP, and Required Evidence}
\fontsize{7.5}{8.4}\selectfont
\begin{columns}[T,onlytextwidth]
\column{.48\textwidth}
\textbf{Responsibility boundary}
\begin{itemize}
  \item \textbf{NDNSF}: protected Request, discovery, ACK closure, producer-owned names, signer/role/dependency admission, recipient-bound CEK grants, and failure state
  \item \textbf{UAV application}: viewpoint/navigation, capture metadata, analysis invocation, annotation schema, and Requester-side overlay
  \item \textbf{Perception backend}: existing per-view detector and deterministic evidence aggregation; it does not decide Provider assignment
  \item \textbf{Autopilot and onboard safety}: stabilization, readiness, geofence and final rejection; collision avoidance requires configured sensing and planning
\end{itemize}
\textcolor{Red}{\textbf{Current implementation work.}} Complete dependency/result admission and Requester-bound CEK grants; integrate frame metadata and annotations.
\column{.49\textwidth}
\textbf{First measurable MVP}
\begin{itemize}
  \item one static outdoor GPS point, three camera roles, three camera UAVs, one GPU Analyzer, and one existing detector
  \item test provider unavailability, mobility, Data loss, missed deadlines, and unsafe-assignment rejection
\end{itemize}
\textbf{Measurements and ablations}
\begin{itemize}
  \item completion, valid-view and analysis success, latency, bytes, image publications per capture, and flight/energy proxy
  \item one versus three views under occlusion; nearest versus geometry-aware selection; Analyzer failure and retry
\end{itemize}
\textbf{Claim boundary}: no new recognition algorithm, moving-target identity, fleet autonomy, triangulation, or 3-D accuracy claim.
\end{columns}

\begin{frame}{Close the Physical Loop Before Publishing a Successful View}
\fontsize{9}{10.5}\selectfont
\begin{enumerate}
  \item \textbf{Locate and plan}: target coordinates/height + aircraft pose $\rightarrow$ reachable viewpoint and camera line of sight.
  \item \textbf{Move and point}: autopilot waypoint + gimbal command $\rightarrow$ observed arrival and settled camera orientation.
  \item \textbf{Capture and check}: trigger camera $\rightarrow$ returned frame, exposure time, sharpness and target visibility.
  \item \textbf{Publish or retry}: bind accepted image to measured pose, calibration, request/plan/attempt; otherwise retry within budget or report failure.
\end{enumerate}
\claim{A command ACK confirms command handling, not a useful image. The service completes only after checking physical feedback and captured content.}
\evidence{Candidate adapter APIs: MAVSDK Telemetry, Camera and Gimbal [4]. Firmware/device support must be verified. NDNSF handles service collaboration; flight stabilization stays onboard.}
\end{frame}

\begin{frame}{Localization and Multi-View Recognition Are Separate Tasks}
\fontsize{9}{10.5}\selectfont
\begin{itemize}
  \item \textbf{Locate the aircraft}: fuse navigation sensors; record pose uncertainty. Define global/local coordinates and altitude reference.
  \item \textbf{Locate the observation}: calibrate camera intrinsics and camera--gimbal--body transforms; align image exposure with pose. A pixel ray needs depth, terrain, or multiple views to infer a world point [5].
  \item \textbf{Recognize across views}: detect per image, associate the same target, reject mismatches, then fuse evidence with uncertainty. Three bounding-box lists alone are not multi-view recognition.
\end{itemize}
\claim{First validate a surveyed static target with per-view results. Add cross-view fusion next; 3-D localization and moving-target tracking require additional algorithms and evidence.}
\evidence{[5] OpenCV calibration/geometry primitives support geometric estimation; they do not provide a complete UAV perception pipeline. Proposed integration, not an implemented accuracy claim.}
\end{frame}

\begin{frame}{Reach the Target Through Four Observable Stages}
\fontsize{9}{10.5}\selectfont
\begin{tabular}{>{\RaggedRight\arraybackslash}p{.24\textwidth}>{\RaggedRight\arraybackslash}p{.65\textwidth}}
\textbf{Stage} & \textbf{Evidence required before expanding scope} \\\hline
1. Sensor bench & Real camera/gimbal APIs, calibration and exposure/pose pairing; verify rejected commands, timeouts and missing frames. \\[.6em]
2. Flight simulation & Software-in-the-loop (SITL), then hardware-in-the-loop (HITL) where supported [6]: close navigation/capture feedback; inject GPS error, occlusion and link loss. \\[.6em]
3. One physical UAV & Surveyed static target; repeatable arrival, pointing and useful captures; compare measured location/latency against ground truth. \\[.6em]
4. Multiple UAVs & Complementary real views and selected Analyzer; verify target association, fusion, bounded retries and loss of one participant. \\
\end{tabular}
\claim{Keep the same service contracts across stages. Promote a stage using recorded measurements, not successful message exchange alone.}
\evidence{[6] PX4 distinguishes simulated flight stacks and hardware-backed simulation. Neither establishes real camera, radio or flight performance. All four stages are proposed work here.}
\end{frame}

\begin{frame}{Define Success Before the Field Experiment}
\fontsize{9}{10.5}\selectfont
\begin{itemize}
  \item \textbf{Freeze the operating envelope}: target size/range, altitude, lighting, wind and allowable location error; select hardware against it.
  \item \textbf{Freeze measurable thresholds}: pointing/position error, exposure--pose skew, valid-view rate, recognition precision/recall and end-to-end p95 latency. Values need bench data, not invented guarantees.
  \item \textbf{Compare on the same trials}: one versus multiple views, per-view results versus fusion; measure added traffic, capture delay and energy alongside accuracy.
  \item \textbf{Exercise failures}: stale GPS, gimbal saturation, missing frames, wrong-view association, Analyzer loss and deadline expiry. Expect bounded retries or explicit failure.
\end{itemize}
\claim{Immediate next deliverable: one real camera/gimbal capture with synchronized pose and independently checked target visibility. Then scale the collaboration.}
\end{frame}

NDNSF was implemented using \texttt{ndn-cxx}~\cite{ndn-cxx}, NDN-SVS~\cite{ndnsvs-github}, and NAC-ABE~\cite{dulal2023nac-abe}. It also includes a configurable NDNSD integration for auxiliary service advertisements~\cite{dulal2022ndnsd}; protected provider discovery uses NDNSF's Request--ACK exchange.

For NAC-ABE, we introduced key caching so cache hits avoid fetching and decrypting the same key again. For NDN-SVS, publications whose encoded Data size is within a configurable limit can be embedded directly in Sync Interest Application Parameters, avoiding a separate publication fetch. We also added regular-expression-based subscriptions to NDN-SVS to filter message types and Request service names; receivers then check the recipient, service and invocation bindings.

NDNSF prepares SVS publications synchronously by default; NDN-SVS also supports an optional worker for asynchronous preparation. Network operations remain on the NDN Face event loop. The evaluation does not isolate the contributions of individual optimizations.

NDNSF validates certificate chains against fixed trust anchors, checks certificate validity periods, and enforces configured application trust rules. Peers can reference immutable, producer-signed security profiles by exact Data name to reuse encryption certificates within their validity periods. Receivers fetch and validate uncached profiles and retain authorization and request-binding checks for each invocation.

A two-provider MiniNDN functional experiment verified protected nonempty input delivery and correct results for both selected providers. The performance experiments below select one provider per invocation.

%Finally, under high-frequency NDNSF workloads, the original blocking APIs and heavily single-threaded design of NDN-SVS became a major bottleneck, since most synchronization and processing logic executed on the main Face event loop. To address this issue, we redesigned Sync Interest handling and publication into an asynchronous pipeline. CPU-intensive tasks such as state-vector processing, decoding, comparison, and metadata preparation are offloaded to a bounded worker pool, while all NDN Face and \texttt{io\_context} operations remain on the main NDN thread to preserve thread safety. In addition, we introduced a nonblocking asynchronous publish path that prevents application-level request handling from stalling the Face event loop. These optimizations significantly improve NDNSF scalability and responsiveness under high-frequency request workloads.

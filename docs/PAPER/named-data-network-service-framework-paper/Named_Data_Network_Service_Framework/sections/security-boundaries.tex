NDNSF trusts the Controller, attribute authority, and configured trust anchors. Certificate-chain and validity checks, trust rules, ABE permissions, and request bindings are required; decrypting a message or matching a token alone does not authorize execution. Providers with matching permissions can decrypt a protected task descriptor, while request-scoped keys restrict input decryption to selected Providers and result decryption to the requesting User. Names and traffic patterns remain visible, and signed feedback does not prove that reported resources or results are correct. Permission changes take effect after participants enforce the updated state; previously disclosed data cannot be retracted.

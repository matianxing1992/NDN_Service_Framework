Distributed service-oriented applications~\cite{channabasavaiah2003migrating} power everything from global cloud infrastructure to real-time industrial automation.  They operate over networks of computers where services are the primary abstraction. For example, in edge AI systems, WiFi and cellular base stations may provide storage and AI inference/training services to end devices, while also offloading compute-intensive tasks to cloud services. As another example, a UAV network may adopt a service-oriented design to coordinate a ground station and multiple drones: each drone exposes flight-control services invoked by the ground station, while drones may also request services from one another (e.g., for sensing or data processing).  Service frameworks provide the software infrastructure to develop, deploy, and manage such applications.  

In today’s Internet, gRPC~\cite{grpc} is widely used for high-performance remote procedure calls, REST~\cite{fielding2000architectural} supports stateless HTTP-based interactions, and message-queue systems~\cite{john2017mqsurvey} enable asynchronous decoupled communication. Despite their widespread adoption, these IP-based frameworks can face limitations in dynamic and large-scale environments. \emph{Scalability} can be constrained when provider selection requires repeated point-to-point exchanges. \emph{Reliability} can be impacted by endpoint binding and load concentration, which create performance bottlenecks and potential single points of failure. \emph{Security} based only on channels protects data in transit; object-level confidentiality requires additional encryption.
% since IP does not natively bind security to named content or enforce fine-grained access control over data objects.

Named Data Networking (NDN)~\cite{zhang2014named} provides an alternative, data-centric networking model in which communication is driven by named data rather than host addresses. Consumers issue Interests to retrieve Data packets. A producer's cryptographic signature, when validated under appropriate trust rules, supports integrity and authenticity; encryption can provide confidentiality. NDN can improve \emph{scalability} through in-network caching and multicast forwarding, allowing multiple consumers to retrieve published Data. It can enhance \emph{reliability} by decoupling communication from fixed endpoints, enabling retrieval from caches or alternative sources under failures or mobility. These properties support secure service-oriented applications.

\emph{Despite the above advantages, building service-oriented applications over NDN remains challenging because discovery~\cite{dulal2022ndnsd}, authorization, and invocation~\cite{meirovitch2021nsc} must be coordinated.} To address this gap, we design the Named Data Networking Service Framework (NDNSF), a modular framework for building secure and distributed service-oriented applications. NDNSF provides three core capabilities: (i) \textbf{service publication and discovery}, (ii) \textbf{fine-grained, name-based access control using attribute-based encryption}, and (iii) \textbf{service invocation with dynamic provider selection}. In particular, NDNSF introduces a \textbf{one-to-many service model with customizable provider-selection strategies}, enabling applications to choose providers based on runtime metrics such as computational capacity, queue state, and network delay. Providers acknowledge requests based on task requirements and current resource availability, allowing users to select among willing participants.

NAC-ABE protects optional task descriptions during solicitation and aggregates an entity's service permissions in one decryption key under one authority~\cite{zhang2018nac,dulal2023nac-abe}. \textbf{Reusable Identity Credentials with Stable Trust Rules} keep signing identities separate from changing service permissions. Permission aggregation is inherited from ABE; we analyze its cost for service permissions.

We evaluate NDNSF against NDN Service Call (NSC)~\cite{meirovitch2021nsc} and gRPC, and analyze credential distribution and update costs. In the original lossy wired experiment with a single provider, NDNSF achieves a higher service-completion rate than NSC and a rate comparable to gRPC. In the tested scenarios with multiple heterogeneous and intermittently unavailable providers in wired and wireless networks, NDNSF achieves higher success rates than fixed-provider configurations by utilizing available providers. We also evaluate the selective acknowledgment mechanism under provider overload conditions and user-defined provider-selection strategies. Matched studies examine task-specific feedback and compare complete invocation paths, including their latency and traffic costs.

NDN~\cite{zhang2014named,afanasyev2018brief} shifts networking from a host-centric to a data-centric communication model.  In this section, we briefly review NDN and two NDN-based mechanisms used by NDNSF.

\subsection{NDN in a Nutshell}

\begin{figure}[]
    \centering
    \includegraphics[width=.9\columnwidth]{figures/ndn-forwarder.pdf}
    \vspace{-3mm}
    \caption{NDN Forwarding Process}
    \label{fig:ndn-forwarder}
    \vspace{-3mm}
\end{figure}

NDN employs a receiver-driven request-response model based on two packet types: \textit{Interest} and \textit{Data}. A consumer sends an Interest packet specifying the desired data name. The network forwards the Interest by name; a producer or an in-network cache may satisfy it. A matching Data packet returns along the reverse path established by the Interest.

To support this process, an NDN forwarder maintains a Forwarding Information Base (FIB), Pending Interest Table (PIT), and Content Store (CS). The FIB stores name-prefix routes; the forwarding strategy uses them to choose next hops. The PIT tracks pending Interests and can aggregate compatible Interests so that a matching Data packet can satisfy multiple consumers. The CS may cache Data packets for future requests, reducing retrieval latency and bandwidth consumption when a cache hit occurs. Figure~\ref{fig:ndn-forwarder} illustrates these structures. Together they support in-network caching, multicast Data delivery, and strategy-dependent forwarding~\cite{yi2013case}.

NDN also adopts a data-centric security model in which Data packets carry signatures. With a producer's cryptographic signature and appropriate trust rules, consumers can verify data authenticity and integrity independently of the communication path or retrieval source, which is particularly advantageous in environments with caching and replicated content.

\subsection{NDN Sync}

In a multi-party distributed NDN application, participants need to learn about newly published data so that they can retrieve it. Distributed Dataset Synchronization, or Sync~\cite{li2018brief,moll2022sok}, exchanges summaries of publication state to reveal updates without a central coordinator. Sync protocols include ChronoSync~\cite{zhu2013let}, PSync~\cite{zhang2017scalable}, and State Vector Sync (SVS)~\cite{moll2021svs}. NDNSF uses the NDN-SVS implementation~\cite{ndnsvs-github} to announce service-message publications; participants retrieve the corresponding Data when needed. NDN-SVS has been tested in both infrastructure-based and infrastructure-free environments~\cite{moll2022sok}.

\subsection{NAC-ABE}

\begin{figure}[]
    \centering
    \includegraphics[width=.9\columnwidth]{figures/kp-abe-scheme.pdf}
    \caption{Encryption and Decryption with KP-ABE}
    \label{fig:kp-abe}
    \vspace{-3mm}
\end{figure}

NDNSF leverages NAC-ABE~\cite{dulal2023nac-abe} to provide fine-grained access control and automated key management.
More specifically, we use Key-Policy Attribute-Based Encryption (KP-ABE)~\cite{goyal2006attribute} provided by NAC-ABE, where data is encrypted under a set of attributes, and each recipient's decryption key (DKEY) encodes an access policy over those attributes.

In NAC-ABE, an Attribute Authority manages system attributes and issues decryption keys for access control (Figure~\ref{fig:kp-abe}). During initialization, it generates public parameters and a master secret key. The public parameters are distributed to participants for cryptographic operations, while the master key is kept by the Attribute Authority to generate recipient-specific decryption keys (DKEYs) according to their authorized access policies. Each data object is encrypted using a symmetric Content Key (CK), and the CK is then encrypted using ABE under the data object's associated attributes. When retrieving data, a participant first obtains the encrypted CK (whose name is included in the data object), then decrypts it using their DKEY. The recovered CK is subsequently used to decrypt the data object itself. This hybrid design applies expensive ABE operations only to the small CK and uses symmetric encryption for the bulk data.

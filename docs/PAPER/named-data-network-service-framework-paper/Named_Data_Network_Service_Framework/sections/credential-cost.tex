\subsection{Credential Management Costs}
\label{sec:credential-cost}
\label{sec:measured-permission-cost}

Signing credentials identify the message signer; DKEYs control access to encrypted service content. Let $N$ be the number of entities, each with at least one permission, and $p$ their average number of permissions. Table~\ref{tab:credential-counts} counts credentials held by entities, including each holder's copy of a shared service key.

Both configurations use one identity-signing credential per entity, counting its certificate and private key together. For this count, the aggregated-ABE configuration uses one ABE authority, shared public parameters and one current DKEY per entity. The separate-service-key column assumes one decryption key per permission; a credential issued per role may cover multiple services. The counts exclude content keys, encryption credentials and authority-side material.

Fewer objects do not guarantee fewer bytes or messages. An aggregated DKEY grows with its policy and may require segmentation~\cite{dulal2023nac-abe}; separate service keys can be batched. Granting a permission may replace the full aggregated key, while a separate-key design can deliver only the added key. Global ABE rotation replaces every remaining authorized entity's DKEY; rotating an affected service key may update fewer entities.

Parameterized trust rules are also reusable in alternative designs~\cite{nichols2019dnmp,yu2015trust}. NDNSF keeps service permissions in ABE policies and Controller state; comparative costs of trust-rule updates, compilation and validation remain unmeasured.

\section{应用实验与结果解释}
单次调用或应用会话提供观测值。比较结果的不确定性通过独立重复运行估计；共享随机种子或轨迹的不同系统按运行配对，不假设同一次运行中的各请求相互独立。

每组比较实验开始前，工作负载定义将明确主要评价指标、完成截止时间，以及何种改善具有实际价值。预实验将用于确定重复运行次数；这些选择在正式比较前固定，并与效应估计及其不确定性一同报告。

为将 RQ1 转化为可测量问题，研究将在确定对照配置前先定义以下授权成本模型。

首个 RQ1 对照在两种设计中保留 ABE 加密发现，只改变调用授权机制：受保护 challenge 与 DNMP-inspired 角色约束签名。两者均保留签名验证、Selection、请求状态、当前服务权限检查及接收者作用域的输入／结果保护。这将授权选择与发现加密分开，不是对原始 DNMP 实现的测量。服务组加密作为单独的敏感性比较。初始授权测试采用一个 User、四个候选 Provider，以及一项获准和一项未获准服务，再扩展配置规模。

UAV 编排对照由 User 转交相同的签名加密图像对象，不改变其生产者身份；直接交换使用指定生产者的名字。两者采用同等保护和相同处理代码。该比较固定图像输入，不检验增加视角能否提高识别效果。DI 数值容差将在运行前根据选定精度声明，不根据观察到的误差事后调整。

每次运行记录工作负载、软件修订和网络配置。对于可观测的状态，分别报告提交、准入、选定、完成、拒绝、超时和取消，并明确分母及截止时间。

延迟分布说明包含哪些请求，并同时报告失败率。单次探索运行应如实标记，不能据此估计运行之间的不确定性。

UAV 会话记录命令完成延迟、视频启动延迟、有效帧交付、录制获取完成及操作员看到的状态年龄。多视角工作还记录可用视角数、处理完成与基于标注观测的分析指标。框架实验首先固定识别算法；声称多视角提升识别准确率需要独立应用研究。

DI 记录模型准备、prefill、首 token 时间、后续输出速率、总完成时间、设备峰值内存及 Provider 间传输字节。Cold 与 warm 分别比较，保留可运行的单 Provider 对照。如果分布式部署源于模型无法装入单设备，应直接报告容量收益，而非相对不可运行基线构造加速比。通信、序列化、密码操作和模型计算分项剖析用于定位瓶颈。

授权评价应覆盖双方服务权限，而不只是解密成功。反例包括无权限调用者、无权限 Provider、签名有效但受保护值错误的消息，以及请求关闭后的重复使用。授予实验测量已登记实体如何发现并应用新权限；撤销实验测量更新传播、状态验证、参数和 DKEY 刷新，以及应用更新后的拒绝。断连节点和旧密文分别检验，并遵守授权论证中说明的限制。

协作消融保留 request-ID 隔离和签名验证。去除指定生产者检查时，测试同一请求内的错误角色对象；去除依赖边检查时，测试来自获准参与者的未声明输入；替换测试注入重新分配后的旧工作。结果记录具体由哪项检查拒绝，以及是否发生禁止的执行。若其他保留检查仍拒绝对象，该实验不能证明被移除检查的独立必要性。合法输入对照用于避免把拒绝全部任务误认为正确执行约束。

框架复用可通过记录 UAV 与 DI 共享的调用、授权、对象传输和生命周期组件，以及仍需应用适配的部分来评价。代码行数不足以衡量可维护性；还需记录增加服务类型所需修改和必须提供的契约。这支撑工程理由，协议正确性与性能则由各自证据支持。

针对表~\ref{tab:framework-boundary} 的边界研究，两类应用将通过相同 NDNSF 运行时路径检验错误生产者、未声明依赖及取消后迟到工作的拒绝。另构造密码学与依赖检查通过但违反应用契约的输入：超出观测时间窗的图像，或声明模型／形状不兼容的张量。记录拒绝发生在哪一层，并确认被拒绝输入不能启动依赖它的应用工作；合法对照仍须完成。形状正确但数值错误的张量说明另一限制：需要参考执行验证数值，签名并不证明正确性。记录各工作负载需要的适配器和运行时修改；重复实现相同检查，或在运行时中新增应用专属分支，都表明需要重新考虑拟议的职责划分。这些结果支撑已测工作负载的共用契约，而非所有服务的普适性。

部署记录应包含依赖版本、模型摘要、拓扑、链路参数、时钟、重试策略、缓存及密钥管理配置，但不公开秘密。应用失败应与启动、配置和结果收集失败分开；环境未建立并不能证明协议无法完成请求。这些记录帮助最终论文区分受支持结论、有价值的负结果和未测试配置。

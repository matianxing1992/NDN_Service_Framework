\section{操作员工作流程与状态解释}
典型会话始于操作员发现感知服务并选定车辆。后续相机或任务操作保持同一设备身份，除非操作员或明确任务策略授权替换。界面将状态关联到产生它的车辆和操作。延迟观测不能被呈现为新命令已经成功的依据，因此观测时间、操作身份及应用过期阈值属于验证契约。

当前 UAV 实验假定相机固定安装在机体上。这是用于简化几何标定的实验配置，不是 NDNSF 的框架要求；因此，车辆姿态扰动及相机到机体的标定仍属于应用层验证问题。

拟议评价使用完整会话，而非只测试孤立按钮：获取状态、启动相机流、查看增量帧、停止直播、查找录制并获取选定记录对象。相机控制采用服务调用；帧交付和录制获取分别使用对应数据路径。实现可以允许无直播查看者时继续录制，因此不能根据流订阅推断记录可用性。测试应记录应用配置是否支持该模式，以及记录引用是否标识正确生产者与版本。

\section{直播视频、录制与感知服务}
直播查看与录制获取具有不同目标。直播优先在延迟预算内交付近期可用帧；延迟帧可能已失去操作价值。录制则需要明确保留期限及可供后续获取的分段标识。流／会话身份、生产者身份及帧或分段序号应防止旧会话的延迟帧混入当前会话。这些是应用验证要求，并不声称所有交付策略已经实现。

测试应分别改变帧大小、生产速率、可用带宽和接收缓冲。降低分辨率或丢弃过时帧可能缩短查看延迟，也可能减少视觉信息，不能无条件视为网络改进。除调用延迟外，还应报告交付帧率、显示帧年龄、缺口和录制完整性。启动录制、访问直播和读取保留对象的权限，应在相应操作或对象边界检查。

感知在采集之外增加计算：感知服务提供命名图像，分析服务获取获准图像并运行固定检测器，请求者获取引用该图像的标注。遥测、相机控制、录制、飞行命令和分析因此检验不同框架路径；多视角协作组合这些路径，而非取代 UAV 应用其余部分。

\section{飞行命令与本地安全}

三层职责需要区分：NDNSF 运行时检查服务授权与请求状态；UAV 应用管理操作员权限与任务状态；车辆及其安全逻辑判断操作是否安全。

除服务调用权限外，评价还将考察特定车辆的操作员权限在哪些位置受到检查。当前地面站检查操作员租约，机载执行处理函数未独立重复该检查。端到端测试将检验命令路径能否拒绝已过期或未获准的操作员命令。

飞行相关服务将应用连接到 MAVLink、PX4 等飞控接口~\cite{mavlink-survey,px4}。提交命令的权限与操作安全不同。地理围栏、车辆就绪、避碰和本地 failsafe 属于车辆或应用安全设计。网络研究应采用有界监督命令和明确失联策略，而不假定服务调用适合所有底层飞控循环。

对有界导航或相机指向操作，应分别记录车辆就绪、命令接纳、观测进度和应用终态。就绪检查包括当前飞控心跳、适用的位置估计、电池状态及允许的飞行模式。飞控命令确认和观测到的车辆状态必须与 NDNSF ACK Data 区分；positive NDNSF ACK 不证明到达航点，旧命令延迟状态也不能使新命令被判为完成。

超时和重连测试须核对适合该车辆及运行条件的本地悬停、返航或降落策略。连续手动控制还需要独立的控制频率和过期命令安全评估，不能仅凭监督调用成功认定安全。固定相机配置下，解释视图还需时间对齐的车辆姿态及相机到机体的标定。服务消息交付本身不证明飞行安全或几何精度。

\section{任务分配与部分失败}
任务进度、重新分配策略与补偿仍由应用负责。NDNSF 运行时承载相关服务交换，不解释车辆任务结果，也不提供物理动作的原子回滚。

多机巡逻可作为次要工作负载：应用划分区域任务、跟踪完成，并决定未完成任务能否重新分配。其相关性在于任务状态及观测与当前分配的关联。这比多视角分析更广，但不应成为无边界的新算法开发要求。后述主要协作实验固定任务和分析方法，以隔离网络与协议效应。

两种工作流都应测试观测缺失、选定 UAV 断连，以及替换决定后的延迟状态。除请求截止时间外，还应报告可行 Provider 实际可达的时间区间。重传与同步不能制造无线覆盖，也不能延长已过期的应用时间预算。因此，即使获取恢复正常，完成率仍可能受到可用性限制。

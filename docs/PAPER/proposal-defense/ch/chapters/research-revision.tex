\chapter{引言}

\section{应用动机与服务级决策}
网络应用组合了生命周期和资源需求不同的服务。UAV 操作员向特定车辆发出命令、跟踪变化的遥测，并获取视频或录制图像；推理应用选择计算资源、获取模型对象并交换中间结果。即使连通性或可用资源变化，开发者仍须保持请求、权限、执行状态和数据对象之间的关联。

请求者可能知道所需服务，却不知道哪些获准 Provider 当前可达、有能力且愿意执行。另一些操作必须保持已经选定的 Provider，例如停止某台相机。因此，框架既要支持运行时选择，也要将后续命令和结果关联到预期的 Provider 与操作。本文中的 User、Provider 和 Controller 是逻辑协议角色：User 请求服务，Provider 提供或执行服务，Controller 管理服务权限；一个节点可以同时承担多个角色。研究问题是如何由可复用框架支持这些决策及数据交换，而不要求每个应用自行定义调用协议。

命名数据网络（NDN）支持按名获取 Data 和以数据为中心的安全机制~\cite{ndn,ndnpacket}。名称标识 Data、指导 Interest 转发并参与信任规则；应用可用 trust schema 约束可接受的签名密钥并指导 Data 验证~\cite{trustschema}。Sync 支持发现数据集变化，以便应用获取可用 Data~\cite{li2018brief,moll2022sok}。NDNSF 用这些基础机制发现 Provider、检查调用权限并跟踪服务执行，详细网络背景在下一章展开。

即使一个 Provider 足以执行任务，应用仍需发现候选、检查权限、选定执行者并取得结果。NFN 提供命名函数与缓存计算模型；NFaaS 是 Named Function as a Service；RICE 是 Information-Centric Networking 中的 Remote Method Invocation；NSC 是 Named Service Calls~\cite{nfn,nfaas,rice,nsc}。Distributed Network Measurement Protocol（DNMP）提供 Trust Schema 命令授权实例~\cite{dnmp}。这些 NDN 系统提供计算、调用与授权先例，作为本 Proposal 分析 NDNSF 设计选择的参照。

\section{初版 NDNSF 的调用基础}
初版 NDNSF 从多个候选中选定一个 Provider。User 发布 Request Data、收集应答（ACK）Data，再发布 Selection Data；选定 Provider 执行并发布 Response Data。候选是同一次调用的替代执行者，不承担不同的相互依赖角色。

发现与授权不以协作为前提。发现描述提供期限和资源需求，应用输入提供执行材料。研究所评价的设计通过属性基加密（ABE）将描述的读取范围限制为持有匹配解密密钥的实体。参与者结合下文定义的受保护 challenge 值（RequestNonce 和 ProviderChallenge）、信任规则下的签名验证、当前权限状态及请求状态检查服务权限。获准但未选中的候选仍可读描述。输入／结果保护、权限授予与撤销和管理成本同样属于评价范围。

\section{从单 Provider 调用扩展到多 Provider 协作}
部分任务需要不同 Provider 提供互补服务。分别调用各服务，并不会自动规定哪个 Provider 担任哪个角色，以及依赖服务可以接受哪些中间对象。本 Proposal 研究在保留调用基础的同时，通过扩展明确这些分工与依赖。

例如，附近无人机（UAV）从不同角度采集地面区域图像，交给计算 Provider 分析。扩展分配采集和处理角色；计算 Provider 检查每张图像是否来自被指定提供该输入的 UAV。UAV 在决定是否返回 positive ACK 前，可能需要区域和截止时间信息。Selection 授权采集任务后，无人机才生成图像。Selection 提供执行详情及所需访问信息，而不是尚未拍摄的图像。descriptor 加密限制谁能读取描述，但不隐藏名称或流量模式。此例说明扩展需求；识别算法仍由应用选择。

\section{论点与研究问题}
核心假设是：统一的命名 Data 协议能够将候选发现与获准执行分开，并在使用中间对象时检查是否满足运行时分配的角色约束。这使 UAV 与推理应用能够共享调用及依赖验证机制，同时保留各自的任务语义。研究通过消息／状态不变量、跨应用共用机制以及完成情况和成本的匹配测量检验该假设，并分别评价单 Provider 调用与多 Provider 协作。
\begin{enumerate}[label=RQ\arabic*.,leftmargin=*]
\item 在何种 User 和服务数量、权限重叠程度、成员变化速率及撤销频率下，相比 DNMP-inspired 的角色约束授权替代方案，ABE-backed 授权能够在受保护的 Provider 发现与调用中提供更合适的保密性—管理成本取舍？
\item 如何扩展基于 ACK 的单 Provider 调用，使候选收集结束后运行时选定的 Provider 获得明确的工作流角色和命名依赖作用域，并且只有在中间 Data 与已提交的生产者、名称、依赖边和执行上下文一致时才接受该 Data，无论它来自生产者还是缓存？
\item 在何种工作负载、网络和失败条件下，ABE-backed 发现、角色／依赖准入及有界恢复能够改善完成情况和时延？在何种条件下，其通信、计算和凭证管理成本会超过收益？
\end{enumerate}
RQ1 评价调用基础，包括适配到 NDNSF 流程的 DNMP-inspired 角色授权加内容加密对照。RQ2 通过 UAV／DI 依赖检验协作扩展。RQ3 评价 RQ1 和 RQ2 所研究机制的效用与成本，而不是引入另一套协议；调用与协作分别测量。

\section{命名计算、调用与服务组合}
命名计算与调用系统为本 proposal 提供了直接先例。NFN 与 NFaaS 研究命名函数、缓存计算或执行放置~\cite{nfn,nfaas}；RICE 提供带认证和安全信息的调用握手~\cite{rice}；NSC 使用应用提供的 Trust Schema 验证签名调用 Interest~\cite{nsc}。DNMP 给出了 schema 约束角色授权的具体实例~\cite{dnmp}。CFN 与 CaSCON 进一步涉及计算图、worker 放置或缓存辅助组合~\cite{cfn,cascon}。因此，命名计算、缓存、工作流组合和角色授权调用本身都不被主张为 NDNSF 的独立创新。

更具体的研究问题是：在正、负 ACK 收集窗口关闭后，如何执行一个晚绑定的协作计划。拟议扩展根据通过资格检查的 ACK 将 Provider 分配到应用角色，并由该分配生成前驱和依赖检查。合法签名只能证明来源，请求标识只能提供关联；二者单独都不能证明中间对象由所需前驱角色的指定 Provider 产生，也不能证明它允许沿声明的依赖边推进。待研究的贡献是运行时分工与 Named Data 准入之间的任务级联系，而不是新发明工作流或 manifest 格式。

比较将在明确假设下检查这种联系，包括缓存获取和替换执行。不能因为某篇文献的简要描述没有列出某机制，就断言该机制不存在；如果已有系统已经执行相同检查，贡献必须收窄为有证据的集成或取舍。

\subsection{DNMP：Trust Schema 授权的具体实例}
DNMP 通过角色约束的签名授权测量
命令~\cite{dnmp}。Network Key 是角色密钥、设备密钥及所分发 Schema 签名层级的
信任锚。客户端根据 \texttt{target}、\texttt{probeType}、\texttt{probeArgs} 和用户的
\texttt{roleType}，从用户已有的密钥中查找 Schema 允许的签名密钥；无匹配时拒绝，
多个匹配时选择权限最小的密钥。接收方 Network Observer Daemon（NOD）仅在
publication 通过 Schema 规定的验证后才调度探测操作。因此，这是真正的命令
授权，不是接受任意合法签名。DNMP 还限制 publication 的生命周期并保留近期
publication 状态以防重放，其假设包括设备时钟大致同步。

\section{受保护发现与权限管理}
NDNSF 使用 NAC-ABE 保护与命名服务权限关联的 Data。在所评价的设计中，NAC-ABE 使用 key-policy ABE（KP-ABE）构造：密文携带服务属性，而每个解密密钥（DKEY）携带持有者的访问策略。增强 NAC-ABE 库提供该构造所需的 KP-ABE 操作~\cite{dulal2023nacabe}。该库是实现依赖，不是 NDNSF 新的协议贡献。借助这一构造，User 可以为获准服务接收者类别发布加密的发现描述，而不必列出当前可达的 Provider 身份；Controller 则签发定义解密范围的策略密钥。NDNSF 通过受保护的 challenge 值、信任规则下的消息签名及当前授权／请求状态检查，将这些权限连接到调用。内容加密提供保密性，组合检查约束参与和执行。第~\ref{sec:abe-rationale-ch} 节解释权限管理的复用及其额外成本。

小而稳定的接收组可能适合普通组密钥；已知 Provider 且权限简单时，签名调用加接收者加密可能更直接。ABE 适合先按服务权限描述接收者、再发现具体身份，以及将多项服务权限与身份签名凭证解耦的需求。策略规模、成员变化、加密成本和 authority 可用性构成限制。

\section{参与者、信任与不保证的性质}
前文的组件说明关注软件模块；本节将 User、Provider 和 Controller 作为协议与信任角色：User 请求服务并选择 Provider；在协作扩展中还协调角色分配。Provider 提供并执行服务。Controller 管理服务权限、密钥分发及签名的授权状态。这些角色不是必须分开的硬件；一个节点可以同时担任 User 和 Provider。

管理组织登记身份并批准服务权限，Controller 管理这些策略。参与者预先配置可信锚，以及身份凭证和 Controller 发布的 Data 的验证规则。User 可能不知道已登记的 Provider 中哪些会参与本次调用。转发器和缓存可交付 Data，但不负责执行授权。模型信任 Controller 和 User 的规划决定，不提供抵抗恶意协调者的共识机制。

攻击者可能观察可见名称和流量、注入非法对象、重放合法旧消息，或在缺少权限时尝试操作。凭证泄露及获准实体主动共享密钥需要额外措施，不能由 ABE 单独防止。计费、任意业务事务、全局最优调度和抵抗所有拒绝服务流量不在本研究主张范围内。

认证通过信任规则下的签名和证书链验证识别签名身份，授权决定是否允许操作，保密性限制谁能解密受保护内容。合法凭证不保证负载报告真实、推理正确或图像内容可信。签名状态只有被获取和验证后才影响本地授权；断连节点不可能被假定立即获知撤销。期限判断必须明确时钟及容许偏差。

\section{拟议扩展：从 ACK 集合到协作计划}
在本文中，candidate snapshot 是 ACK 收集窗口关闭时观察到的、通过验证且符合资格的 Provider 报价的规范化有序集合。每条记录包含 Provider 身份以及用于资格判断的签名报价／ACK 信息，例如服务能力和有效期数据；snapshot digest 是该规范化编码的密码摘要。逻辑请求由 request ID 标识；execution attempt ID 区分该请求的一次执行，包括替换执行；execution identity 是 request/attempt 二元组。一个 attempt 的 snapshot 在提交后不可变；替换必须使用新的 attempt，不能静默复用旧分配。

当前 NDNSF 实现已能关闭候选收集、检查已分配的快照摘要、验证选定 Provider 属于该快照，并拒绝冲突计划提交。这些机制为协作研究提供实现基础。剩余研究将依据下文规则，评价中间对象准入、恢复和跨应用行为。

扩展将选择问题从挑选一个执行者变为分配互补任务角色。应用提供角色／依赖模板、所需服务、约束和期限。模板可以手工编写，不要求新发明自动规划算法。ACK 窗口关闭后，可替换策略从合格 positive ACK 中分配 Provider。冻结的是本次已观察到的候选，不是全网所有可能参与者；执行时仍需重新检查资源。

在拟议设计中，User 签名的 Plan Manifest 包含请求标识、candidate-snapshot digest、角色分配、命名依赖边、授权／密钥范围与执行身份。plan digest 来自不含自身 digest 字段的规范化计划正文。Provider 验证签名计划后才导出本地依赖检查；长期证书不指定本次分工。User 必须记录已提交计划并拒绝同一执行身份下的不同计划。这是受信 User 模型下的本地状态机规则，不是签名本身的性质，也不抵抗 User 故意签署冲突计划。

技术困难在于：抽象依赖图可以在发现前确定，但具体签名身份与对象命名空间尚不能固定。因此，拟议协议将应用模板与 ACK 后的具体绑定分开。各消费者从同一已提交分工导出允许的前驱、对象名称约束及密钥范围；迟到 ACK 不能只改变某个消费者的解释。这不同于等待任意输入就绪，但不证明最优放置，也不提供恶意规划者之间的一致性。

\section{命名对象准入与恢复}
按拟议准入规则，下游 Provider 接受依赖前先检查执行仍然活动且未超出截止时间，再验证信任规则下的 Data 签名。新生成输入须匹配请求、计划、执行身份、指定前驱及声明边；历史输入则须满足下文的显式复用授权。两者都须满足名称、格式及密钥范围约束。所需分段须全部通过验证；不完整或格式错误的对象不能满足依赖。生产者、缓存和仓库获取执行相同检查。计划引用实际生产者授权命名空间中的对象，而不以其他生产者身份重新发布。

拟议恢复规则区分重新获取对象与重复计算。Provider 应用替换后，旧执行消息及回调不能推进新执行。

只有新签名计划明确引用现有成果的精确不可变标识、原生产者与来源、目标依赖及允许的密钥范围，才可复用。成果保留原名称与签名，不伪装成本轮新生成对象。消费者检查这项显式复用授权，而不是要求历史成果携带新的执行身份；其余旧对象仍不可接纳。

应用还须判断图像是否仍满足时间要求或张量／状态是否兼容。因此，旧成果可以继续使用，但旧执行的消息不能推进替换后的执行。应用补偿不提供分布式原子事务，也不保证物理操作恰好执行一次。

RQ1 评价授权设计及替代方案。RQ2 通过错误角色与依赖边、重放、取消，以及生产者／缓存对象的一致验证，检验计划和状态规则。这些协作实验将扩展后续评价章中的调用证据。

\section{有条件的正确性论证}
前述准入论证以签名密钥未泄露、信任和授权检查正确执行，且 Provider 遵守规定状态机为条件。若要保证仅在 Selection 后执行，所有启动处理函数的路径都须检查活动分配，并确认一次性授权状态尚未被用于启动执行。

若要落实声明的依赖约束，所有输入路径（包括从缓存获取）都须检查依赖边及指定生产者；历史成果则须具备显式复用许可。引用须确定精确 Data，例如包含隐式摘要的完整名称，或经验证且包含内容摘要的分段 manifest。

替换后，旧 worker 和迟到回调不得推进新执行。重启恢复须保留相关一次性状态，或使其安全失效。有效签名和缓存 FreshnessPeriod 本身不能保证这些性质。

研究将通过同请求内的错误角色对象、合法签名生产者提供的未声明输入，以及重分配后的迟到回调，检验这些有条件的不变量。各案例分别检验 request ID 本身不能表达的性质。论证范围是所述假设下的协议接纳与执行状态；应用结果正确性及物理副作用需要单独验证。

\chapter{基于 NDNSF 的 UAV 应用}
\label{chap:uav-ch}
\label{chap:applications-ch}
NDNSF-UAV 通过控制、遥测、视频、录制及协作感知，检验服务发现、授权、数据交付和执行管理。单 Provider 操作检验调用基础，多视角采集进一步检验互补角色。第六章给出对照方案和测量方法。

\section{应用结构与服务流程}
UAV 应用连接操作员地面站与无人机侧服务容器。无人机通过 NDNSF 暴露相机操作、遥测和任务相关服务；地面站也可以提供目标检测服务，因此同一应用包含服务消费与服务提供两类行为。应用解释相机、飞行器和任务数据，NDNSF 提供可复用的调用与数据交付机制。

这些操作检验不同的框架要求：选择当前可用的感知 Provider 检验发现与 ACK 选择；控制已选定的飞行器检验与该 Provider 关联的调用，而不是任意替换执行者。遥测和任务状态获取检验返回 Data 与目标飞行器及活动操作的关联。长任务为取消、截止时间和迟到状态提供验证场景。测试必须区分拒绝非法命令与飞控实际执行获准命令。

直播和录制使用不同的数据路径。相机 Start/Stop 是服务控制操作，随后直播使用命名数据流接口；录制引用与完整存储对象则需要精确对象获取，不能依赖缓存必然持久保存。这些功能因此可以检验流生命周期、顺序和缺口处理、内容保护及数据产品获取。编解码、图像处理、操作界面和飞行安全仍由应用负责，但它们对 NDNSF 的使用同样属于框架验证范围。

\section{代表性协作：多视角采集与分析}
操作员在地图选择目标位置或区域。Request Data 携带评估覆盖、视角、传感器及时间可行性所需的服务级受保护描述。合格 UAV 返回 positive ACK。拟议工作流分配互补采集角色与处理角色，通过 Selection 交付执行细节及适当密钥。

每个采集 UAV 在自身授权命名空间签名发布加密的 ViewImage Data，附观察时间及可用姿态／标定信息。处理 Provider 获取获准图像、执行规定分析并发布签名的 Annotation Data；给请求方的加密结果包含原图引用及获准分享的图像密钥。请求方获取图像并显示标注，不需要在另一个生产者身份下重新发布原图。

Global Positioning System（GPS）不能单独确定视线、深度或跨视角对应。声称提高识别或定位精度仍需 ground truth、单视角对照及确定的融合方法。MiniNDN~\cite{minindn} 与 PX4 Software in the Loop（SITL）~\cite{px4} 分别检验网络行为及应用／飞控集成，不等同实飞安全认证。

\chapter{基于 NDNSF 的分布式推理}
\label{chap:di-ch}
NDNSF-DI 是 NDNSF 之上的 distributed-inference（DI）应用。它通过单 Provider 推理和模型协作执行，检验发现、授权、模型与张量交换及执行管理。其计算和保留状态与 UAV 的感知及外部动作形成不同的工作负载。第六章评价两类应用共用的框架机制及应用专属检查。

\section{应用结构与推理流程}
NDNSF-DI 是框架之上的推理应用层，解释模型和任务描述，组织模型准备与执行，并向调用方提供结果。原生请求方与 Provider 接口包含请求提交、服务注册、结果／事件处理和取消，会话相关接口还携带续接状态。接口存在并不表示所有模型或恢复配置都已通过端到端测试。

Python 绑定适配同一原生 C++ 路径，不维护第二套请求状态机。

NDNSF 运行时提供可复用的操作、完成通知和事件读取机制；DI 定义模型准备、放置、张量契约、K/V 兼容规则，以及何时将已完成的一轮推理写入会话状态。

单 Provider 推理不需要模型切分，也可以检验服务发现、权限检查、选择、受保护输入交付与结果获取。冷模型准备与驻留模型复用检验不同的就绪和模型文件访问路径。模型文件等对象可使用受管理的 Repo 存储；Content Store 仍是机会缓存，不保证持久保存。DI 定义模型身份、兼容性与放置策略，NDNSF 提供服务生命周期及命名对象交换。

流式推理与会话流程将验证扩展到增量输出、取消、终态和请求特定状态。模型权重、activation 与 key/value（K/V）状态具有不同生命周期。模型计算 K/V 张量，推理运行时保留它们用于后续解码；共享缓冲区可避免每步复制整个 cache~\cite{ortkvcache}，但权重驻留不能替代这些状态。DI 负责分词和 KV 兼容规则，框架验证关注应用使用这些状态时所经过的授权请求、数据交换与生命周期。评价须将本地 K/V 复用收益与 NDNSF 通信及执行机制的收益分开。

\section{代表性协作：多 Provider 推理}
候选收集关闭后，规划器根据已准备的模型及通过验证的 ACK 报价选择切分和 Provider 分配。选定 Provider 认证 Selection 后准备或复用被分配的资源。pipeline 切分分配连续层或层组；tensor 切分分割算子／张量，并需要相应 collective 交换。Provider 沿声明依赖交换 activation 或 collective 输入。Open Neural Network Exchange（ONNX）~\cite{onnx} 描述计算图，导出模型本身不会完成跨 Provider collective 或证明数值正确。模型切分已有相关工作~\cite{neurosurgeon,ddnn}；NDNSF 的问题是运行时分配与获准的命名数据执行。

自回归生成还将生成的 token 用于后续解码，这是时间依赖，不同于逐层前向计算。评价分别测量模型准备、prefill、首 token、后续解码、状态存储和数据传输；结论限于测试过的模型、精度、切分与设备。单 Provider 可运行时保留基线；若模型不能放入单设备，可以论证分布式可行性，但不能计算相对无法运行基线的加速比。

\section{核心研究范围与可行性}
首个 UAV 图将包含两个图像采集角色和一个分析角色；匹配对照使用相同图像与识别算法。首个 DI 用例以双 Provider YOLO 切分为目标，将所有跨切分边界的张量声明为依赖。模型版本、切分点、精度、输入集合及数值容差将在图兼容性检查后、比较实验前固定。可运行的未切分执行提供数值参考和性能对照。这些是计划配置，不是已完成验证。

最低范围包括两个图中的合法完成、非法输入拒绝及各一个受控取消／替换用例。其他切分策略、LLM 流式、更大规模部署及真实飞行试验属于扩展，不是这些有限框架结论的前提。已有控制、遥测、视频和单 Provider 推理流程保留其验证作用。若任一核心图无法通过验证，对应 RQ2 主张仍缺少支持，须与委员会重新考虑范围或时间。分析将报告有益和不利的运行条件。

验证从本地正确性测试逐步扩展到受控 MiniNDN 实验、UAV 仿真与台架集成，以及支持的物理设备。各阶段只为被测环境提供证据。实际飞行实验需要适当批准；仿真本身不能证明实飞安全或感知性能。

\chapter{结论}
本学位论文研究 NDN 之上的可复用服务框架，以初版 NDNSF 从多个候选中选定一个 Provider 完成调用的能力为基础，评价调用及数据交换机制，并扩展到互补的 Provider 角色和命名依赖。

RQ1 将明确权限重叠、成员变化及撤销频率改变时，适合 ABE 权限复用或完整角色授权替代方案的条件。RQ2 将确定 ACK 收集后的分工如何约束新对象及显式复用对象，同时不允许旧执行的消息推进替换后的执行。RQ3 将通过 UAV／DI 工作流测量收益与成本，并检验哪些检查可以由框架共用，哪些需要应用专属验证。

这些是拟议设计与协议贡献，不是新密码学原语或首次命名计算。已有实验支持有限调用结论；协作与跨应用主张仍需其声明的端到端证据。本 Proposal 请委员会评估研究范围、对照方案、验证标准和完成计划的可行性。最终学位论文将报告有证据支持的答案和限制，包括拟议机制不能带来优势的条件。

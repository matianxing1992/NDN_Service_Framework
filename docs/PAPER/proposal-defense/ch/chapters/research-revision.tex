\chapter{引言}
\label{chap:introduction}
\section{从具体任务提出问题}
操作员希望获得某个地面位置的多角度图像，并由具备算力的 UAV 或边缘节点完成分析。附近 UAV 的视角、传感器、电量与可用性不同。请求者知道需要哪些服务，却不能预先假定哪些 Provider 此刻可达并愿意参与。应用因此需要发现候选、分配采集与处理角色，并明确每张中间图像的生产者和使用者。多视角识别是验证任务，不是本文声称新发明的识别算法。

discovery descriptor 是 Provider 判断是否参与所需的信息，例如区域、截止时间、传感器和算力要求；application input 是被选中后执行任务所需的输入。这是用途上的划分，并非固定字段列表。判断覆盖所需的位置属于 descriptor，仅处理阶段需要的图像可以等到 Selection 后提供。即使没有原始图像，区域和时间也可能暴露操作意图。因此本研究保护 descriptor Content 不被缺少相应解密能力的公众读取；获准但未选中的候选仍能读取，名字和流量模式也不会因此隐藏。

\section{NDN 已有能力及其边界}
NDN 通过 Interest 按名获取 Data；签名在适当信任规则下支持完整性和生产者认证~\cite{ndn,ndnpacket}。缓存可代替原生产者满足后续 Interest，但不保证持久存储或截止时间内交付。签名本身不证明执行权限、特定任务的新鲜性或结果语义正确。Sync 帮助发现数据集更新，再通过 Interest 获取相应 Data~\cite{li2018brief,moll2022sok}；它不改变 NDN 为无请求的 Data 推送网络。

NFN、NFaaS、RICE 和 NSC 已经研究命名计算或服务调用~\cite{nfn,nfaas,rice,nsc}。NDNSF 的动机不是“没有其他 NDN 服务框架”。研究对象是运行时发现、服务授权与任务依赖检查的结合及其代价。也不能断言主机导向框架不支持动态发现；例如 gRPC 支持可扩展名字解析~\cite{grpcresolver}。比较必须面向完整配置。

\section{论点与研究问题}
拟验证的论点是：服务框架可以用命名且可验证的对象，把运行时 Provider 选择连接到明确的执行规则，并区分服务级发现保密性和请求级输入／结果保密性。收益具有条件；必须以任务需求说明额外发现、验证和密钥管理成本为何值得承担。
\begin{enumerate}[label=RQ\arabic*.,leftmargin=*]
\item NDNSF 如何发现愿意参与的 Provider，同时避免未获准者读取发现描述，并在执行前检查服务权限？相对完整替代设计，其成本是什么？
\item 如何让运行时选定的 Provider 按任务角色和命名依赖执行，而不依赖中间 Data 来自生产者还是缓存？
\item 在何种任务和网络条件下，这些机制改善完成率、时延或执行效率？何时成本超过收益？
\end{enumerate}
UAV 与分布式推理是共同验证这三个问题的两类工作负载，不因实现了两个应用就自动形成两项研究贡献。恢复是协议与评价的一部分，不预设为独立创新。

\section{贡献与证据边界}
预期贡献为：有比较依据的发现／授权设计；把运行时分工转为命名对象准入规则的协议；有配置边界的实证结论。ABE、Trust Schema、Sync、缓存、模型切分与 challenge-response 均为复用机制。最终论文需区分本人、合作者及已有软件的贡献；本稿不虚构共享代码的个人归属。

这是修订后的 Proposal，不是已经完成的 dissertation。v0.1、后续实测活动、当前实现与目标验收是不同类别。已有 request ID 检查将通过验证的消息关联到活动请求；标识本身不认证消息或授予权限。不能把假设的旧恢复轮次混用说成历史单次 attempt 协议已证实的缺陷。协作与原生 DI 必须独立通过端到端验收。

\chapter{相关工作与完整替代方案}
\section{不能把调用本身当作尚未解决的问题}
NFN 研究命名计算与表达式求值，NFaaS 研究命名函数执行放置~\cite{nfn,nfaas}。RICE 握手支持认证与安全信息交换~\cite{rice}。NSC 使用应用提供的 Trust Schema 验证签名调用 Interest，并讨论输入和结果保护~\cite{nsc}。实验中的简化 harness 不等同于完整 NSC 设计。

NDNSF 的较窄问题是：如何先收集当前意愿与可行性，再选择执行角色，并约束中间对象的使用。长期服务权限并不确定本次哪个 Provider 是指定前驱；request ID 和单独的合法签名也不表达该分工。但把字段写入 manifest 并不自动构成创新。最终需逐项比较 CaSCON~\cite{cascon} 等服务组合、工作流安全及 capability 系统，而非声称首个 NDN 服务框架。

DNMP 是角色约束命令签名与验证的具体先例~\cite{dnmp}。角色粒度由策略决定：一个角色可以覆盖多种操作，规则允许时也可以复用凭证。

本比较为 DNMP-inspired 授权补充请求状态检查与内容加密。这是作为 NDNSF 替代方案需要满足的要求，不是声称 DNMP 原论文实现了 NDNSF 的消息流程。

选定后的交换使用接收者专属加密。保密发现还需要在选出本次参与者之前分发解密能力，例如组密钥管理或 ABE；这些并非穷尽全部选择。Trust Schema 单独不提供保密性，但与适当加密结合后可以满足这一要求。

证书式撤销需要验证者获取足够新的撤销状态，或者等待证书过期。删除仓库中的证书不能使已缓存副本自动失效。这是公平替代方案的生命周期要求，不是声称 DNMP 原论文实现了 NDNSF 的运行时撤销流程。

\section{从保密需求到架构收益}
NDNSF 的两条关联设计目标是：选择 Provider 之前的保密发现，以及将分发与细粒度内容访问分离。为此，User 加密发现描述并发布可共享获取的密文，Controller 签发具有不同访问范围的策略密钥。增强 NAC-ABE 库提供 KP-ABE 支持~\cite{dulal2023nacabe}。NDNSF 在调用中复用这套权限管理：参与者核验受保护的 challenge response、信任规则下的消息签名，以及当前授权和请求状态。这些检查与内容加密职责不同。撤销和换钥属于有成本的生命周期要求，不是独立的优越性证据。第~\ref{sec:abe-rationale-ch} 节展开这些选择及边界。

小而稳定的接收组可能适合普通组密钥；已知 Provider 且权限简单时，签名调用加接收者加密可能更直接。ABE 适合先按服务权限描述接收者、再发现具体身份，以及将多项服务权限与身份签名凭证解耦的需求。策略规模、成员变化、加密成本和 authority 可用性构成限制。

\chapter{系统模型与协议}
\section{参与者、信任与不保证的性质}
这些是协议角色，不是必须分开的硬件；一个节点可以同时担任 User 和 Provider。管理组织登记身份并批准服务权限，Controller 管理这些策略。参与者预先配置可信锚及身份凭证／Controller 材料验证规则。不知道本次哪些候选会回复，不等于授权机构从未登记它们。计费、任意业务事务、全局最优调度和抵抗所有拒绝服务流量不在本研究主张范围内。
User 请求并协调调用；Provider 提供并执行服务；Controller 管理授权材料与签名状态。转发器和缓存可交付对象，但不负责应用执行授权。模型信任 Controller 和 User 的规划决定，不引入抵抗恶意协调者的共识协议。攻击者可能观察可见名字／流量、注入非法对象、重放合法旧消息或在缺少权限时尝试调用。凭证泄露及获准实体主动共享密钥不由 ABE 单独解决。

认证通过信任规则下的签名和证书链验证识别签名身份，授权决定是否允许操作，保密性限制谁能恢复 Content。合法凭证不保证负载报告真实、推理正确或图像内容可信。签名状态只有被获取和验证后才影响本地授权；断连节点不可能被假定立即获知撤销。期限判断必须明确时钟及容许偏差。

\section{授权与保密性}
\input{\proposalroot/ch/chapters/authorization-rationale}
发现 descriptor 的保密范围是缺少相应 ABE 解密能力的实体，不排除其他获准候选，也不隐藏流量。选定后设计使用请求级对称密钥保护输入和结果，将所需密钥加密给经过认证的选定 Provider 公钥。图像对称加密与公钥封装图像密钥不是同一操作。响应密钥由 User 和选定 Provider 共享，因此不能说只有 User 知道结果明文；准确说法是其他 User 在密钥未泄露的假设下不能解密。此处描述目标保护路径，不回填为全部 v0.1 路径的历史行为。

\section{ACK 集合到协作计划}
应用提供角色／依赖模板、所需服务、约束和期限。模板可以手工编写，不要求新发明自动规划算法。ACK 窗口关闭后，可替换策略从合格 positive ACK 中分配 Provider。冻结的是本次已观察到的候选，不是全网所有可能参与者；执行时仍需重新检查资源。

在拟议设计中，User 签名的 Plan Manifest 包含请求标识、候选快照、角色分配、命名依赖边、授权／密钥范围与执行身份。摘要来自不含自身 digest 字段的规范化计划正文。Provider 验证签名计划后才导出本地依赖检查；长期证书不指定本次分工。User 必须记录已提交计划并拒绝同一执行身份下的不同计划。这是受信 User 模型下的本地状态机规则，不是签名本身的性质，也不抵抗 User 故意签署冲突计划。

\section{命名对象准入与恢复}
按拟议准入规则，下游 Provider 接受依赖前必须验证信任规则下的 Data 签名、当前请求／计划、指定前驱角色的生产者、允许的名字／数据格式／密钥范围及声明的依赖边。分段不完整或格式错误不能满足依赖。直接获取、缓存获取和仓库获取执行相同检查。对象使用实际生产者的授权命名空间，消费者通过引用复用对象，不把别人生产的数据改名为自己的 Data。

\section{有条件的正确性论证}
假定签名密钥安全、信任／授权检查正确、Provider 遵守状态机：全部启动路径须核验活动 Selection 及未使用的一次性授权状态；全部输入路径（含缓存）须核验指定生产者和声明边。重分配须隔离旧 worker 和迟到回调。重启须保留相关状态或使其安全失效；签名和 FreshnessPeriod 不能替代这些检查。

这些是有条件的不变量和实现论证义务，不是完整系统的密码学证明。反例应包括同请求错误角色、合法签名生产者提供未声明边、重分配后迟到回调，分别检验 request ID 本身不表达的性质。应用结果语义及物理副作用仍不属于该论证。

\chapter{应用验证}
\section{UAV：多视角采集、处理与返回}
主案例是地图上的地面位置请求，而非完整自主任务系统。发现时只提供判断覆盖、视角、传感器及时间可行性所需的受服务权限保护的信息。候选返回 ACK，计划选择互补采集角色和处理角色，Selection 交付执行细节及密钥。

在拟议 UAV 流程中，采集 UAV 签名包含加密图像内容的 ViewImage Data，在自己的授权命名空间发布，并附观察时间及可用姿态／标定元数据；内容加密不隐藏外层 Data 名称。GPS 不足以独立确定视线、相机方向、深度或跨视角对应；应用需规定采集容差、视角质量和失败处理。处理 Provider 按授权边获取图像，执行规定分析并发布 Annotation Data，返回原图引用并在给请求方的加密结果中提供获准分享的图像密钥。User 获取原图和标注后绘制叠加结果，不要求重新发布同一原图。

框架主指标是截止时间内完成授权的采集—处理—返回。只有声称提高识别／定位精度时，才另外要求 ground truth、单视角对照与确定的融合算法。MiniNDN~\cite{minindn} 和 PX4 SITL~\cite{px4} 可分别检验网络及应用／飞控接口，但不等同实飞安全认证。控制、直播、录制与巡逻功能是支持工程，不全部变成毕业验收项。

\section{DI：计算、数据与状态依赖}
pipeline 切分分配连续层或层组；tensor 切分分割算子／张量并需要相应 collective。ONNX~\cite{onnx} 表示计算图，导出模型本身不会完成跨节点 collective 或证明数值正确。模型切分已有相关工作~\cite{neurosurgeon,ddnn}；NDNSF 的候选增量是运行时分配和命名依赖检查。

截至本次 2026 年 9 月修订，原生 V3／兼容性和集成验收仍未全部关闭。本地测试不等同跨进程、多设备或封装环境资格。较早小模型实测不证明 canonical-layer reuse、tensor/hybrid、多加速器放置或 LLM 恢复。最终固定模型、精度、切分、显存、网络、冷热状态和输出容差；单设备能运行则保留基线，不能运行则只论证分布式可行性，不计算虚构加速比。

\chapter{结论}
NDNSF 的候选贡献是服务协议及有证据支持的机制选择，不是新密码学原语或首次命名计算。RQ1 比较受保护发现与 ABE 权限复用的适用条件；RQ2 把运行时分工变成本地命名依赖准入规则；RQ3 测量完成、时延、执行效率与代价。已有实验支持有限调用结论；协作与跨应用主张仍需其声明的端到端证据。本 Proposal 据此给出可核查的 dissertation 完成路径。

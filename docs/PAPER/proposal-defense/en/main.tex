\begin{abstract}
Networked applications need mechanisms for service discovery, invocation authorization, and application-data exchange. Changes in service availability, resources, or connectivity make these tasks more challenging. Named Data Networking (NDN) provides data-centric communication primitives, but applications still need service-level mechanisms. This dissertation investigates these mechanisms through the Named Data Networking Service Framework (NDNSF) and its extension to multi-Provider collaboration.

NDNSF provides reusable service interfaces and Request, acknowledgment (ACK), Selection, and Response Data exchanges. Its initial prototype selects one Provider per invocation: before selection, the Request carries a discovery descriptor readable only by Providers authorized for the requested service; after selection, request-scoped keys deliver the application input only to the selected Provider. NDNSF uses attribute-based encryption (ABE) to protect the discovery descriptor from parties lacking the required decryption capability. The User need not enumerate Provider identities, but authorized candidates can read the descriptor even if they are not selected. Service authorization combines signature validation under trust rules with current service-permission checks. Successful matching of the protected RequestNonce and ProviderChallenge values provides evidence that the parties recovered the values required for the current exchange, while request-state checks reject replayed or stale invocations. Permissions remain separate from identity-signing credentials; runtime grants and withdrawals require validated status and key updates. After selection, request-scoped keys protect application input and results for the intended participants.

The proposed collaboration extension assigns roles to Providers whose positive ACKs pass validation and eligibility checks. Each Provider derives its input-validation rules from the signed plan. The plan binds assigned Providers to service roles and declared dependency edges. These checks constrain which intermediate Data may advance execution, including Data retrieved from caches. The study also examines known-Provider invocation, trusted local composition, streaming, and retrieval of large objects by name.

Two applications provide validation settings: the unmanned aerial vehicle (UAV) application covers control, telemetry, video, and multi-view analysis; the distributed-inference application covers model retrieval, single-Provider inference, and collaborative execution of model partitions. Preliminary experiments report configuration-specific invocation latency and the number of executions observed under each configuration; they do not yet validate the collaboration extension. Planned evaluation compares complete authorization alternatives, tests dependency enforcement and recovery, and measures completion, latency, communication, computation, and credential-management costs. The expected contribution is an evaluated framework and evidence identifying when its mechanisms benefit dynamic applications and when their overhead limits those benefits.
\begin{keywords}
Named Data Networking, service authorization, provider discovery, collaboration, distributed inference
\end{keywords}
\end{abstract}

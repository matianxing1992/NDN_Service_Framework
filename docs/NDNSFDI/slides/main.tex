\begin{frame}{2. prepare(): Validate and Publish Model Materials}
\small
\begin{enumerate}
\item \textbf{Before prepare:} export trained model files to ONNX and configure the model description and model-specific processing code.
\item \textbf{Read and validate:} check graph/weight hashes, supported operations, input/output tensor formats, and size limits.
\item \textbf{Publish retrievable layers:} store the graph, weights, and layer indexes in a Repo---a named-data storage service. Each assigned layer can then be retrieved by reference.
\item \textbf{Return a prepared handle:} retain model references and validation metadata for later requests, without starting inference.
\end{enumerate}
\point{Preparing retrievable layers does not assign them to Providers. Assignment happens later, using Provider feedback.}
\small \textbf{Preparation cache:} reuse a ready entry or share an in-progress preparation. Active handles keep the entry in use; configured limits control retention and refresh.
\src{Runtime.cpp: source loader and User::prepare; ModelPreparationCache.cpp; NativeRequestCatalog.cpp.}
\end{frame}

\begin{frame}{3. request(): Use Provider Feedback to Assign Layers}
\begin{center}\begin{tikzpicture}
\node[box,text width=28mm](a){Request\\\scriptsize requirements + references};
\node[box,text width=29mm,right=4mm of a](b){ACK feedback\\\scriptsize willing and capable?};
\node[box,text width=29mm,right=4mm of b](c){Placement strategy\\\scriptsize assign roles/layers};
\node[box,text width=29mm,right=4mm of c](d){Selection\\\scriptsize authorize assigned work};
\draw[arr](a)--(b);\draw[arr](b)--(c);\draw[arr](c)--(d);
\end{tikzpicture}\end{center}
\small
\begin{itemize}
\item The User specifies the task, deadline, generation budget, and model/input references---not the full model in every Request.
\item Providers return acknowledgment (ACK) feedback. A positive ACK indicates willingness; the User also checks eligibility.
\item After ACK collection closes, the User's placement strategy decides which Provider executes each layer group and which intermediate outputs it needs.
\item Selection tells each chosen Provider what to execute and supplies the protected references and authorization needed for that work.
\end{itemize}
\point{A positive ACK offers participation. Only a validated Selection permits the assigned execution; an ACK does not reserve resources.}
\src{PreparedModel.cpp; native planning/Selection path; Spec189 r259 affinity evidence.}
\end{frame}

\begin{frame}{4. After Selection: Reuse, Fetch, Assemble, Load}
\small
\begin{enumerate}
\item \textbf{Verify the assignment:} validate authorization, model identity, selected role, and permitted layer/material references.
\item \textbf{Check local model data:} reuse files only when their model version, assigned layers, authorization, and validity match this request.
\item \textbf{On a miss, retrieve assigned materials:} express Interests for the required Named Data; verify and decrypt the retrieved materials.
\item \textbf{Assemble a model fragment:} combine the assigned layers and weights; define tensor inputs from preceding layers and outputs for subsequent layers.
\item \textbf{Load the fragment:} create an ONNX Runtime session. This loaded session and its execution wrapper are called the \textbf{runner}.
\end{enumerate}
\point{Having model files on disk does not mean the model is loaded in memory. Loading can still be required.}
\small \textbf{Validation limit:} the completed three-turn test used a cache-compatible path; it did not validate the full encrypted-Repo retrieval and reuse path.
\src{Provider.cpp; ProviderArtifactCache.cpp; NativeCanonicalOnnxAssembler.cpp; Spec190 T003/T006.}
\end{frame}

\begin{frame}{5. Prefill and Decode Across Two Providers}
\begin{center}\begin{tikzpicture}
\node[box,text width=28mm](u){User input\\\scriptsize prompt or new turn};
\node[box,text width=32mm,right=9mm of u](a){Provider 0\\\scriptsize earlier layers + local KV};
\node[box,text width=34mm,right=12mm of a](b){Provider 1\\\scriptsize later layers + local KV\\\scriptsize token selection};
\draw[arr](u)--(a);
\draw[arr](a)--node[above,font=\scriptsize]{activations}(b);
\draw[arr](b.south)--++(0,-9mm)-|node[pos=.25,below,font=\scriptsize]{selected token / next-step feedback}(a.south);
\end{tikzpicture}\end{center}
\small
\begin{itemize}
\item \textbf{Prefill:} process input tokens and compute attention keys and values (KV). Each Provider retains KV for its own layers.
\item \textbf{Decode:} use the previous token and cached KV to compute the next token. Activations are intermediate tensors passed between model fragments.
\item Arrows show logical dependencies: each consumer retrieves and validates Named Data before its next step; Data is not unsolicited push.
\item The last Provider publishes generated tokens for the User. End-of-sequence (EOS) or the token limit stops generation; finalization saves continuation state.
\end{itemize}
\src{NativeEpochCoordinator.cpp; ONNX model runner; Spec189 r259/r260 generation evidence. KV = attention keys/values.}
\end{frame}

\begin{frame}{7. Restore KV and Continue the Next Turn}
\small
\begin{enumerate}
\item \textbf{Save progress:} each Provider retains its layers' attention keys/values (KV) for a limited time. A checkpoint identifies the processed token prefix and references the retained state.
\item \textbf{Keep a continuation record:} the conversation journal stores authenticated checkpoint and Provider references, not the full KV tensors.
\item \textbf{Choose Providers again:} prefer previous Providers if still authorized and suitable; this preference does not reserve them.
\item \textbf{Restore compatible KV:} verify the model, assigned layers, token history, retained state, and expiry before reuse.
\item \textbf{Continue inference:} process the new input tokens, then generate output using the restored and newly extended KV.
\end{enumerate}
\point{Restored KV saves prefix computation. The model runner must also be ready; keeping KV alone does not eliminate session loading.}
\small If retained KV is unavailable or invalid, report failure unless a supported path can rebuild it by processing the token history again.
\src{Conversation.cpp; Spec189 r259 retention/affinity and r260 KV\_RESTORED evidence.}
\end{frame}

\begin{frame}{8. Keep the Model Loaded---Within Explicit Limits}
\begin{columns}[T]
\begin{column}{.48\textwidth}
\begin{block}{Verified: within one request}\small
One loaded runner per selected role is reused across generation steps and finalization \textbf{within a request}.

\medskip Three turns on two Providers required \textbf{6 runner preparations}: one per Provider per turn, not one per generated token.
\end{block}
\end{column}
\begin{column}{.48\textwidth}
\begin{block}{Target: reuse across turns}\small
Retain an idle loaded session when memory budget and lifetime permit; reuse it for a compatible, newly authorized request.

\medskip Limit total retained memory and idle time. Keep active runners alive, release unused entries when needed, and check authorization for every new request.
\end{block}
\end{column}
\end{columns}
\point{When memory is available, keeping a compatible runner can avoid loading it again. Retaining the runner does not automatically retain or validate a conversation's KV.}
\small Keeping a loaded runner across requests is a target, not a result established by the three-turn test.
\src{NativeEpochCoordinator.cpp: request-local runner slot; Spec189 r260; Spec190 T007.}
\end{frame}

\begin{frame}{9. Where the Large Resource Costs Occur}
\small\renewcommand{\arraystretch}{1.05}
\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}p{34mm}YY@{}}
\toprule\textbf{Operation}&\textbf{Main cost drivers}&\textbf{Reuse opportunity}\\\midrule
ONNX export / preparation&Graph processing, weight reads, temporary memory&Export once; retain prepared package\\\midrule
Repo publication&Encryption, hashing, storage writes, transferred bytes&Reuse immutable published materials\\\midrule
Provider material retrieval&Network transfer, validation, decryption&Fetch only assigned layers; eligible local hits\\\midrule
Assembly / session loading&Graph and weight copies, disk I/O, runtime allocations&Reuse assembled artifacts and loaded sessions\\\midrule
Prefill / decode&Compute, growing KV memory, activations each step&Reuse prefix KV; avoid per-token runner loading\\\bottomrule
\end{tabularx}
\point{Encryption/decryption can temporarily retain several full-model buffers, not just a key. These buffers may overlap with assembly and loaded runners on the same host.}
\src{Spec190 T003 resource evidence. Cost drivers are structural, not a measured ranking; stage-level timing/bytes remain needed.}
\end{frame}
